# Срез37 — авторизация получения прачечной

Допущение: укрепляем существующий `confirm_receipt` перед добавлением действия в общую карточку. UI, API и правила начисления не меняются.

## Критерии приёмки до реализации

1. Сохранённая квитанция после ожидания блокировки профиля и отзыва сессии не выдаётся: `SERVICE_SESSION_INVALID`.
2. Свежая команда после ожидания фолио и отзыва сессии отклоняется без изменения вещей, заказа, начислений, аудита и outbox.
3. Отзыв сессии при позднем ожидании строки заказа откатывает уже подготовленное начисление и смену статусов.
4. Действующая сессия проходит те же ожидания; повтор команды возвращает исходную квитанцию с одним точным bigint-начислением.
5. Закрытый фолио и неразрешённая претензия по-прежнему блокируют получение; порядок блокировок, ACL, API и старые checksum сохранены.
6. Гонки достигают реальной блокировки (`pg_locks` и PID блокирующего соединения), имеют таймаут и выполняются под `views_app` без superuser/BYPASSRLS.

## Граница гарантии

Проверяем конкретные ожидания профиля, фолио и заказа. Это не глобальная атомарность logout со всеми операциями при READ COMMITTED: отзыв после последней проверки может пересечься с завершением команды. Хранение вещей и финансовые записи остаются одной транзакцией.
