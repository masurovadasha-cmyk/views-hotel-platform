# M0d.1 — одноразовая локальная песочница

Требования: Linux, Node24, Docker, зависимости из frozen pnpm10.18.3 install.
Из корня: `pnpm dev:local` (или `npm run dev:local`). Команда собирает веб/API,
создаёт собственную PostgreSQL16, проверяет checksum миграций и применяет synthetic
seeds. Постоянная views_local и /workspace/.views-local не используются.

После sandboxReady в stdout доступны номера случайных loopback портов Core и web.
Локальный режим гостя выбирается параметром `?api=guest-core`. Это инструкция для
локальной машины, не публичный preview. Проверены readiness, HTML, отсутствие
сессии и отказ401 для поездок без входа. Письма не отправляются: адаптер отсутствует,
форма входа покажет ошибку недоступности доставки. Это пока не полный бизнес-сценарий.

Ctrl+C/SIGTERM после bootstrap закрывает HTTP и удаляет только собственный
контейнер с временной БД. Все данные песочницы теряются при остановке. Во время
bootstrap сигнал откладывает выход до безопасной точки; SIGKILL cleanup не гарантирует.
Убийство машины может оставить контейнер: не удалять чужие/постоянные контейнеры.

Проверки: `npm run dev:local -- --smoke` — полный запуск и автоматическая остановка;
`node scripts/dev-local-lifecycle.cjs` после сборки — запуск и SIGTERM после readiness.
Запускать lifecycle proof без параллельных Core proofs (он сравнивает список контейнеров).
Вручную: открыть гостевой экран, убедиться в явной ошибке неподключённой доставки,
закрыть Ctrl+C и проверить, что постоянные сервисы остались нетронутыми.

Нет hot reload, персонала и Next/Expo оболочек. Следующий срез — минимальные
каркасы приложений; M0 целиком ещё не закрыт. Зависимостей и миграций БД не добавлено.
