# Срез30 — доступ при создании и повторе заказа уборки

Продолжение: [срез31 — повторная отправка отзыва](CLEANING_FEEDBACK_REPLAY_AUTHORIZATION_31.md); ниже сохранены результаты среза30.

Критерии приёмки:
1. Сохранённый ответ после ожидания ключа требует действующей сессии и текущего владельца брони.
2. Logout, отвязка профиля и смена основного гостя во время ожидания исключают возврат квитанции.
3. Проверка сессии выполняется после ожидания брони/профиля; новая команда проверяет её также после каталога.
4. Отказ не создаёт заказ, задачу, начисление или audit/outbox; runtime остаётся views_app без superuser/bypassRLS.
5. Разрешённый повтор после выезда или изменения каталога возвращает исходный ответ без новой покупки;
   изменённое тело с тем же ключом остаётся конфликтом.
6. Гонки подтверждаются pg_locks и PID блокирующего соединения, с ограниченным ожиданием и освобождением locks.

Решение: новая migration0121 заменяет только app.guest_cleaning_request. Возврат replay
переносится после блокировки брони/профиля и проверки доступа, до текущих бизнес-ограничений.
После catalog FOR SHARE повторяется проверка сессии новой команды. Прежние сигнатура,
payload, порядок блокировок и правила цены/начисления сохраняются. Миграции и checksum
предыдущих версий не переписываются; новых таблиц, прав или зависимостей нет.

Запуск synthetic-среды: `npm run dev:local`.
Проверки: `npm test`, `npm run build`, API `npm run typecheck && npm run build`,
`node scripts/core-network-primitive-gate.mjs`, `node --test scripts/staff-mail.acceptance.cjs`,
`VIEWS_GUEST_EMAIL_HTTP_PROOF=true VIEWS_GUEST_EMAIL_BROWSER_PROOF=true node scripts/cloud-core-tests.cjs src/supply src/service-orders src/staff-auth`.

Что проверить вручную: создание уборки → потеря ответа → повтор с прежним ключом;
после logout/смены владельца отказ; после выезда доступный владельцу replay не создаёт новую уборку.
Риск READ COMMITTED: отзыв доступа, завершённый после последней проверки, может следовать
за уже разрешённой операцией; глобальная атомарность logout со всеми запросами не обещается.
Таймаут остаётся неизвестным результатом до ручного повтора. Остальные команды услуг
требуют отдельной проверки. Persistent БД и публичные web/Cloudflare/APK не меняются.
