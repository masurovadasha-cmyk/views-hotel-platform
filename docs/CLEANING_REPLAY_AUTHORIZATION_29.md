# Срез29 — доступ при повторе команды уборки

Критерии:
1. Повтор отмены и переноса времени после ожидания ключа проверяет текущую сессию.
2. Отвязанный профиль и смена основного гостя во время ожидания дают такой же отказ,
   как обычное отсутствие доступа; сохранённый результат не возвращается.
3. Новая команда сохраняет проверки после ожидания, отказ не меняет заказ/задачу/фолио/audit/outbox.
4. Разрешённый повтор сохраняет прежний ответ даже после смены стадии/выезда;
   изменённое тело с прежним ключом остаётся конфликтом, новых записей нет.
5. Гонки проверяются разными runtime-соединениями с наблюдаемым ожиданием pg_locks,
   ограниченными таймаутами и освобождением блокировок даже после ошибки.

Migration0120 заменяет только app.guest_cleaning_change: возврат сохранённого ответа
переносится после прежних блокировок брони/профиля/заказа/задачи и проверки сессии,
но до проверок ревизии/стадии. Порядок блокировок, payload и финансовая логика сохранены.
Старые миграции/checksum не меняются; новых таблиц/индексов/прав/зависимостей нет.
API и экран используют прежний контракт. Исправление касается отмены/переноса уборки;
прочие команды не объявляются прошедшими такую же проверку.

Запуск: `npm run dev:local` в synthetic-среде. Проверки: `npm test`, `npm run build`,
API `npm run typecheck && npm run build`; `node scripts/core-network-primitive-gate.mjs`,
`node --test scripts/staff-mail.acceptance.cjs`,
`VIEWS_ORDER_LIST_BROWSER_ONLY=true VIEWS_GUEST_EMAIL_HTTP_PROOF=true VIEWS_GUEST_EMAIL_BROWSER_PROOF=true node scripts/cloud-core-tests.cjs src/supply src/service-orders src/staff-auth`.
Ручная проверка: потеря ответа отмены → повтор с прежним ключом; отзыв доступа → отказ;
история после выезда. Таймаут остаётся неизвестным результатом до ручного повтора.

повтором; глобальной атомарности logout со всеми запросами не заявляем. Persistent БД не меняем.
