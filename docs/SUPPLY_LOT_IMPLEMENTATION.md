# Остатки партий: разбиение на срезы — 14 октября 2026

Статус: план реализации, код учёта партий ещё не написан. Migration0108 хранит сведения о поступлении, но не доказывает текущий остаток партии.

## Найденные зависимости

- Migration0067 добавляет инвентаризационные корректировки и revision.
- Migration0080 резервирует товар V Market по SKU;0082 оформляет выдачу.
- Migration0091/0092 возвращает товар после инспекции.
- Старые выдачи не содержат партии: восстановить текущие партии по приходам достоверно нельзя.

Ограничение: нельзя объявлять количество поступившего товара текущим остатком партии. Нельзя менять только ручное списание, оставляя выдачи маркета и корректировки вне новой модели. Проверять все пути физического движения и конкурентные операции.

## Срез L1 — подтверждённая инвентаризация партий
Цель: сотрудник физически пересчитывает партии одного SKU и подтверждает начальное распределение текущего остатка без изменения его общей величины.
Критерии:
1. Сумма распределения равна текущему общему остатку; неизвестная партия явно выделена, даты не выдумываются.
2. Предпросмотр связан с revision; изменение физического остатка требует нового расчёта и подтверждения.
3. Проверяются stock.manage, объект/организация, replay и конфликт одного ключа с другим содержимым.
4. Черновик/подтверждённый снимок не выдаётся за живой остаток; любое следующее физическое движение делает снимок устаревшим.
5. Экран показывает дату сверки и статус актуальности; тесты гонки сверки/движения и повторной команды.
Артефакты: добавочная миграция снимков/строк, API preview/confirm/read, форма, критичные тесты. Не включать новые правила продажи.

## Срез L2 — распределение всех физических движений
Цель: единый журнал распределяет приход, ручную выдачу, выдачу V Market, возврат и корректировки по партиям атомарно с общим складом.
Критерии: сумма остатков партий равна SKU; нет отрицательных партий; общий порядок блокировок; повтор не создаёт распределение дважды; нельзя обойти учёт прямой записью движения; остаток неподтверждённого происхождения явно неизвестен. Возврат не наследует партию без подтверждённой связи. Тесты каждого пути и гонок выдачи/резерва/корректировки обязательны.
До выполнения всех критериев L2 не включать режим «живые остатки партий». Если L2 превышает лимит diff, разделить подготовку схемы и адаптацию команд под отключённым флагом, не включать частичную модель.

## Срез L3 — правила выбора и годности
Цель: согласованные правила FEFO и допуска товара учитываются в выборе партии и доступности гостевого каталога.
Критерии: дата объекта, явные правила для неизвестной годности, ручной выбор с аудитом, запрет выдачи запрещённой партии, пересчёт доступности резерва, уведомления без автоматической финансовой операции. Значение expiry «годен до начала/конца дня», карантин и категории товаров — проверить с операционным владельцем; не вшивать юридические допущения.

## Запуск и ограничения
Текущий код и миграции не изменены. Применять будущие миграции только штатным runner с проверкой checksum. Интеграционные тесты — одноразовая PostgreSQL16, не persistent views_local. Тесты реализации не запускались: это документационный срез. Публичный веб/APK и Canva-статусы не изменяются.
