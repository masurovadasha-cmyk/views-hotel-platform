# VIEWS 0.10.0-preview — адаптация по Canva

Подготавливается обновление веб-предпросмотра и Android по трём присланным
документам: Guest App — 9 страниц, Staff CRM — 17, Design System — 6.
Все **32 страницы** рассмотрены, включая обложку и заключительную страницу CRM.
Это не утверждение о полной функциональной готовности каждого описанного экрана.

Изменения блока: тёплый ivory/gold интерфейс гостя, рабочий indigo-интерфейс
сотрудников, общие состояния темы и соединения, более ясный маршрут бронирования,
локальный предпросмотр заявки услуги, поиск и фильтры очередей CRM, доступные
детали задач. Красный используется для смысловых предупреждений и ошибок.
Точные CSS-токены выбраны при реализации, не выданы за извлечённые значения Canva.

Публичный режим остаётся **static-demo**. Реальные email, платежи, документы,
публичный PostgreSQL Core и отправка заявок не включаются оформлением экранов.
Существующие девять ролевых входов и направление «Закупки и склад» сохраняются;
выбор роли в URL не назначает права аккаунту.

Большой Design Pack на 60 страниц не получен из-за ограничения скачивания
32 MiB и не объявляется интегрированным. Файл Vertex на 50 страниц также не
получен; Vertex остаётся отдельным продуктом. Источники с SHA-256, решения и
ручная приёмка описаны в [заметке интеграции](CANVA_2026_10_09_INTEGRATION.md),
полное сопоставление доступных страниц — в [матрице](CANVA_SCREEN_PARITY.md).

## Параметры и воспроизведение

- Версия: `0.10.0-preview`; Android versionCode: `1000001`.
- applicationId: прежний `uz.views.preview`, Android 8+, target SDK 35.
- Подпись: тот же существующий preview-ключ, без ротации или нового applicationId.
- Источники: чистый окончательный commit; `release.json`, APK assets и evidence
  должны указывать этот же SHA и `sourceDirty=false`.

Использовать [процедуру сборки и подписания 0.9](RELEASE_0_9_PREVIEW.md), заменив
версию, tag и имена файлов на `0.10.0-preview`, `v0.10.0-preview`,
`VIEWS-0.10.0-preview.apk`. Старые APK/evidence предварительно сохранить.
Не использовать старые checksum/source SHA при проверке нового артефакта.

Перед сборкой релиза выполнить typecheck, unit-тесты, новую Canva browser proof,
проверки ролей/локализации, публичный портал и Android assets. После подписания
проверить `apksigner`, `zipalign`, fingerprint прежнего сертификата и встроенный
source SHA. Наличие подходящего versionCode и сертификата не заменяет физическую
проверку установки поверх 0.9 на телефоне.

Публикация использует существующие Pages/Cloudflare staging и GitHub prerelease,
без объединения main и включения публичного Core. После публикации проверить
metadata обоих веб-адресов и скачать APK из GitHub Release для повторной сверки
SHA-256. Workflow артефактов должен закреплять новую версию, checksum и commit.

## Свидетельства проверки и публикации

До фиксации release-коммита прошли frontend307/56, normal/review build,
Canva214layout/54guestcontrast, guest/staff localization HTTP fixtures,
portal и9role-entry proof. Финальная сборка повторяет Canva proof, включая
контраст календаря, и проверяет Android assets/signature. Исторические Core476
не выдаются за новый локальный прогон этого frontend-блока.

Финальный чистый source SHA, результаты сборки/публикации и SHA-256 скачанного
APK записываются в [GitHub Release v0.10.0-preview](https://github.com/masurovadasha-cmyk/views-hotel-platform/releases/tag/v0.10.0-preview)
после проверки доставки. Локальный build не заменяет внешний release.json.

Отдельно остаётся ручная приёмка на физическом Android: установка поверх прежней
версии, холодный старт, клавиатура, системная кнопка «Назад», обе темы, три языка,
фотографии и повторное открытие без сети. Браузерная проверка не доказывает работу
нативного WebView и не подтверждает соответствие WCAG без измерений.
