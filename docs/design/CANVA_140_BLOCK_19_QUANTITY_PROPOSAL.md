# Canva19 — согласование меньшего количества V Market

SG-MK-004, SD-MK-002, SS-MK-001: склад предлагает уменьшить одну позицию до сборки; гость видит весь новый состав, актуальную сумму и принимает или отклоняет. Критерии: только stock.manage; целое количество1..50 строго меньше исходного; исходный резерв до согласия; отмена предложения без изменения резерва; повторное согласие создаёт один заказ; начисление только после получения согласованного состава.

Migration0104 совместимо расширяет существующий proposal workflow. Блокировки брони/заказа, повторная проверка роли/владения, revision, audit/outbox и идемпотентность сохранены. Новый action propose_quantity принимает expectedRevision, fromServiceId, quantity, note; деньги считает сервер. Proposal.kind=quantity; существующие accept/decline/withdraw остаются. Старые миграции не меняются.

При согласии существующий market_replace атомарно заменяет резерв и создаёт связанный новый заказ; старый снимок не меняется. При отказе/ошибке исходный заказ сохраняется. Сумма рассчитана по актуальному каталогу: уменьшение количества не гарантирует уменьшения общей суммы при изменившейся цене, поэтому гость подтверждает весь состав и сумму. Это не частичное начисление за уже переданные товары.

## Запуск и проверки
```sh
npm run build
npm --prefix apps/api run typecheck
npm --prefix apps/api run build
npm test
VIEWS_GUEST_EMAIL_HTTP_PROOF=true VIEWS_GUEST_EMAIL_BROWSER_PROOF=true node scripts/cloud-core-tests.cjs src/service-orders/market.input.test.ts src/service-orders/market.integration.test.ts src/service-orders/market-adjustments.integration.test.ts
```
Только disposable PostgreSQL16 и synthetic fixtures; persistent views_local не сбрасывать.

Ручная проверка: выбрать заказ с количеством2+, отправить уменьшение до1, сверить состав/сумму у гостя, отказать и проверить исходный резерв; повторить с согласием, провести сборку/выдачу/получение и проверить фолио. Проверить RU/UZ/EN, обе темы, узкий экран, потерю ответа и обновление.

Ограничения: нельзя увеличить количество, уменьшить до0 или менять после начала сборки. Отсутствующий товар целиком, частичная выдача после сборки, фото, партии, провайдерские возвраты — отдельные срезы. Полная PDF-приёмка остаётся открыта, public web/APK не опубликованы.

Проверено на dirtyf83591a: Core31, web367, API/web typecheck/build, network187, mail15 PASS. Новые входные и финансовые проверки сначала падали; после исправления проходят. Connected browser V Market проверяет складское предложение, явное согласие (кнопка заблокирована без checkbox) и отказ гостя с сохранением исходного заказа. Принятие, повтор и начисление проверены Core/PostgreSQL integration test. Полное Light/Dark/PDF-соответствие новой формы пока не принято.
