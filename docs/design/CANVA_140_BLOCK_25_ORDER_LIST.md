# Блок25 — общий список заказов гостя

SG-GN-006: список четырёх действующих Core-направлений. Полная приёмка PDF ещё открыта.
Схема/API не меняются: services/orders, laundry, market, concierge с reservationId.
Новых прав, интеграций и зависимостей нет; использование памяти ограничено загруженными страницами.

Критерии:
1. Явная загрузка получает четыре первые страницы своей поездки без команд/начислений.
2. Фильтры направления и active/completed/cancelled относятся к загруженным данным;
   delivered/handed_over/answered остаются активными до подтверждения гостя.
3. Деньги сохраняются строками bigint: исходная сумма заказа, оценка или расчёт прачечной.
   Бюджет/переписка консьержа не попадают в карточку; сумма не подтверждает оплату/возврат.
4. Независимые cursor: laundry/concierge по2 записи, cleaning/market по50; догрузка без дублей.
   UUID-порядок не называется хронологией; время/ETA не выводятся из неоднозначного requestedFor.
5. Ошибка любого направления очищает список; offline/смена поездки/сессии исключают поздние ответы.
   Повтор ручной; SESSION_INVALID закрывает текущую сессию через существующий guard.
6. Открытие ведёт в направление услуги; после возврата требуется свежая загрузка списка.
   RU/UZ/EN, Light/Dark, мобильный экран390px и отзыв привязки поездки проверяются браузером.

Запуск: `npm run dev:local` — существующий disposable Core/PostgreSQL, только synthetic.
Проверки: `npm run build`, `npm test`, API `npm run typecheck && npm run build`,
`node scripts/core-network-primitive-gate.mjs`, `node --test scripts/staff-mail.acceptance.cjs`,
затем `VIEWS_GUEST_EMAIL_HTTP_PROOF=true VIEWS_GUEST_EMAIL_BROWSER_PROOF=true node scripts/cloud-core-tests.cjs src/supply src/service-orders src/staff-auth`.
Для отладки только нового браузерного сценария добавьте `VIEWS_ORDER_LIST_BROWSER_ONLY=true`.
HTTP-проверка прачечной теперь создаёт собственный юнит и не зависит от побочных fixtures других тестов.

Компромиссы: одна недоступная услуга блокирует весь снимок, чтобы не выдавать неполный список за полный.
Нет серверного поиска/фильтра по всем страницам, общей хронологии, перехода к конкретному ID или новых поставщиков.
Проверить вручную: читатель экрана, длинные названия, пустой фильтр при оставшихся страницах,
возврат из услуги после изменения заказа. Общий guard внешнего выхода/привязки брони остаётся отдельной задачей.
