# Canva 140 — оценка, повтор и история услуги

Развитие SG-GN-006, SG-GN-009, SG-GN-010 и SG-CL-006 для действующего
локального процесса уборки. Полная визуальная приёмка этих ID ещё не завершена.

## Что реализовано

После независимой инспекции гость может один раз поставить оценку 1–5 и
оставить необязательный комментарий до 500 символов. Оценка доступна также
после выезда. Это внутренняя обратная связь по услуге, не публичный отзыв о
проживании: комментарий виден автору и управляющему в пределах объекта,
не выдаётся исполнителю и не копируется в общую квитанцию/outbox события.
Повтор с прежним ключом возвращает прежний результат; новый ключ не позволяет
оставить вторую оценку. Изменение оценки после отправки пока не предусмотрено.

Кнопка повтора завершённой/отменённой уборки заново получает актуальный каталог
для того же проживания. Она не создаёт заказ. Гость видит текущую цену, заново
выбирает время и подтверждает начисление. Core повторно проверяет ревизию,
цену, активность услуги и даты при создании. Отключённую услугу или услугу после
выезда повторить нельзя. Это не автоматический выбор свободного слота.

После выезда история и оценка сохраняются в интерфейсе, форма нового заказа и
переноса скрыта. История читается независимо от каталога, который доступен
только во время проживания. При утрате связи брони с аккаунтом доступ исчезает.

## Схема и API

- Миграция `0074_service_feedback_repeat.sql`: `service_order_feedback`, один
  ряд на заказ, ограничение оценки/комментария, составной FK организации/объекта,
  индекс по объекту/времени, FORCE RLS. Прямой записи runtime-роли нет.
- `POST /v1/guest-identity/email/services/orders/:id/feedback`, тело
  `{rating: 1..5, comment: string}`, UUID Idempotency-Key, гостевая сессия.
- `GET /v1/guest-identity/email/services/orders/:id/repeat`: только чтение
  актуальной цены; никаких списаний, резервов и автоматического заказа.
- Обе очереди получают разрешённую им проекцию оценки. Гостевой BFF требует
  CSRF для записи; права повторно проверяются в SQL после блокировок.
- Начисления и цены исполненного заказа при оценке не изменяются.
- Сиды рабочего фонда не добавляются. Тесты создают синтетические заказы и оценки
  только в БД с маркером `VIEWS_DISPOSABLE_CORE_TEST`.

## Запуск

```sh
npm run build
npm test
npm --prefix apps/api run typecheck
npm --prefix apps/api run build
VIEWS_GUEST_EMAIL_HTTP_PROOF=true VIEWS_GUEST_EMAIL_BROWSER_PROOF=true node scripts/cloud-core-tests.cjs
```

Используется существующее локальное окружение и отдельная временная PostgreSQL.
Новые зависимости, внешние аккаунты, расходы и изменения постоянной БД не нужны.
Публичный Core по-прежнему отключён. Эти изменения не включены в опубликованный
APK `0.14.0-preview`; они сохраняются в ветке разработки до следующего выпуска.

## Что проверить вручную и ограничения

- До инспекции оценки нет; после неё и после выезда оценка разрешена.
- Повтор после потери ответа создаёт одну оценку, один аудит и одно событие.
- Чужая бронь, отозванная сессия и удалённая привязка не дают доступа.
- Управляющий видит комментарий своего объекта, исполнитель его не получает.
- Текст с HTML отображается текстом, не выполняется. Проверить RU/UZ/EN и темы.
- При повторе новая цена видна до подтверждения, согласие снято, время очищено.
- В отсутствие сети запись недоступна; неопределённая операция повторяется тем
  же ключом. Сохранение команды после принудительного закрытия ещё не реализовано.
- Чаевые, публичная публикация, модерация/жалобы на отзывы, окно подачи,
  редактирование и аналитика рейтингов требуют последующих блоков. Штрафы и
  удержания из зарплаты по оценке не начисляются автоматически.

Вопросов владельцу для этого блока нет. Следующий процесс по очереди — прачечная:
опись вещей, согласование окончательной цены, исполнение и возврат вещей.

## Проверки

Рабочее дерево поверх `eeddc45` (до коммита этого блока):

- Веб: сборка/typecheck и 316 тестов в 59 файлах.
- Core: сборка/typecheck и 497 тестов в 85 файлах на временной PostgreSQL 16.
  Отдельно — 20 тестов сервиса/валидации после ограничения состава квитанции.
- Сквозной HTTP/BFF/Core/browser: оценка с потерей ответа и повтором ключа,
  просмотр управляющим, экранирование HTML, получение изменённой цены без
  автоматического заказа, снятое согласие/очищенное время и история после выезда.
- Регрессии: гостевые поездки/привязка/отмена, 9 входов сотрудников, фолио,
  закупки/склад, гостевая сессия и loopback SMTP — успешно, без внешних отправок.
- Сетевой gate: 176 файлов, нарушений нет. Почтовые acceptance: 15/15.

Первый полный прогон обнаружил комментарий в старой версии SQL-квитанции;
после удаления этого поля новая миграция и полный прогон прошли. Текст самой
оценки сохранён в защищённой таблице. Физический Android и публичный Core
в этом блоке не проверялись и не включались.
