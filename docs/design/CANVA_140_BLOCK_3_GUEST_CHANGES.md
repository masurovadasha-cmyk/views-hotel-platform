# Canva 140 — изменение заказа гостем

Продолжение SG-GN-008 и SG-CL-004, не полная приёмка всего PDF.

## Поведение

Гость проверяет условия, подтверждает отмену либо новое время. Core разрешает
изменение только владельцу проживания и только до начала уборки. Сотрудник и
гость видят одинаковое актуальное время. При пересечении с назначением другой
уборки весь перенос отклоняется. Цена и длительность заказа заморожены.

Отмена бесплатна: в этом пилоте нет предоплаты, начисление появляется лишь после
независимой инспекции. Экран не сообщает о несуществующем банковском возврате.
Начатые и принятые работы не отменяются этим методом. Финансовая претензия после
исполнения — отдельный ещё незавершённый процесс.

## Миграция, API и интерфейс

- `0073_guest_cleaning_changes.sql`: узкая SECURITY DEFINER функция с повторной
  проверкой сессии/владения после блокировок. Существующие RLS-политики не расширены.
- `POST /v1/guest-identity/email/services/orders/:id/actions`: `cancel` либо
  `reschedule`, обязательные ревизия и UUID Idempotency-Key; перенос принимает UTC.
- BFF проверяет гостевую cookie, CSRF, разрешённый путь и ключ операции.
- `GuestCleaningChange.tsx`: предварительный просмотр и явное согласие, RU/UZ/EN,
  существующие светлая/тёмная темы, запрет действий без сети, повтор с тем же ключом
  после неопределённого сетевого результата.
- Оригинальные коммерческие данные `service_orders` неизменны. Текущее расписание
  хранится в `service_cleaning_tasks.scheduled_period`; обе очереди читают его.
- Аудит и outbox событий `service.guest_cancel` / `service.guest_reschedule`
  записываются в одной транзакции с изменением и квитанцией идемпотентности.

## Запуск проверки

Из корня репозитория после установки зависимостей:

```sh
npm run typecheck
npm test
npm run build
cd apps/api
npm run typecheck
npm run build
cd ../..
VIEWS_GUEST_EMAIL_HTTP_PROOF=true VIEWS_GUEST_EMAIL_BROWSER_PROOF=true node scripts/cloud-core-tests.cjs
```

Последняя команда создаёт изолированную временную PostgreSQL и синтетические
учётные записи, запускает HTTP/BFF и браузерные проверки и удаляет только свой
контейнер. Нельзя заменять её адресом постоянной `views_local` или запускать
синтетические сиды на рабочем фонде. Пилот доступен только в локальном test-режиме
с `VIEWS_SERVICE_ORDER_PILOT_ENABLED=true`; публичный Core не включается.

## Риски и ручная приёмка

- Проверить отмену одновременно с нажатием сотрудником «Начать»: успех должен
  получить только один запрос, начисления при отмене быть не должно.
- Проверить перенос, занятое окно, границы проживания, прежнюю цену после изменения
  каталога и отображение нового времени в обеих очередях.
- Проверить чужую бронь, просроченную сессию, устаревшую карточку и повтор запроса.
- Проверить RU/UZ/EN, обе темы, мобильный экран и часовой пояс устройства.
- Проверить отсутствие сети и потерю ответа: повторяется прежний ключ, новая
  операция до разрешения результата недоступна. Принудительное закрытие страницы
  пока не сохраняет неопределённую команду; перед повторным заказом проверить историю.
- Нет push/SMS об изменении, автоматического переназначения или согласования окна
  с партнёром; outbox — запись события, а не подтверждение доставки уведомления.
- Нет полной визуальной приёмки SG-GN-008. Партнёрские услуги и изменение цены
  требуют собственных правил отмены/возврата и пока не используют этот метод.

Вопросов для продолжения внутренней реализации нет. Внешние провайдеры остаются
отдельным этапом подключения и юридической проверки.

## Проверенные сценарии

Рабочее дерево поверх `cd88ffef1031d081220b8dbc41e951ebedced2a0`:

- Веб: typecheck, build, 316 тестов / 59 файлов.
- Core: typecheck, build, 493 теста / 85 файлов, включая 13 интеграционных
  сценариев сервиса. Новая миграция применена к временной PostgreSQL 16.
- SQL: чужой гость, устаревшая ревизия, отозванная сессия, занятый исполнитель,
  границы проживания, неизменность первоначального запроса/цены/длительности,
  однократная отмена, освобождение слота и гонка отмена–начало.
- Браузер + реальный BFF/Core/PostgreSQL: перенос гостем, отмена второго заказа,
  выполнение первого сотрудником, инспекция, ровно одно начисление, CSRF,
  согласие, три языка и потеря ответа с повтором того же ключа.
- Сетевой gate: 176 файлов, нарушений нет; почтовые acceptance-проверки 15/15.

Первый браузерный запуск встретил старую review-сборку в `dist` и остановился
до формы входа. После `npm run build` повторный запуск проверяет обычный клиент;
публичный демонстрационный режим этим не изменяется.
