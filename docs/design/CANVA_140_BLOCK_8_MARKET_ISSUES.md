# Canva 140 — обращения V Market

Базис: `cd24ab3`. Расширены SG-MK-004 и SD-MK-002 из переданного PDF.
Это локальная функциональность, не полная визуальная приёмка экранов.

## Процесс

После выдачи или завершения заказа гость сообщает о недовозе/повреждении
(3–1000 символов). Обращение отображается на карточке заказа у гостя и склада.
Склад отвечает гостю; ответ не означает подтверждённую компенсацию.
Пока обращение открыто, подтверждение получения/начисление заблокировано.
После ответа гость может подтвердить фактическое получение либо сообщить
о проблеме повторно. Автозакрытия и обещанного SLA пока нет.

Сумма принятого заказа и складские движения не изменяются обращением или
ответом. После уже выполненного начисления жалоба также не сторнирует фолио.
Возвраты денег, физический возврат на склад, согласованные замены и недовоз
с частичным начислением остаются отдельным незавершённым блоком.

## Данные и доступ

Новая миграция `0084_market_issues.sql`; старые миграции не изменены.
`market_orders.issue` хранит последнее обращение и ответ. История команд
сохраняется существующим механизмом commands/audit/outbox. Это не полноценный
диалог: интерфейс показывает только последнее обращение и ответ.
Используются существующие FORCE RLS и запрет прямых записей runtime.
Новые действия существующего API: `report_issue` (гость), `answer_issue` (stock.manage),
поля `expectedRevision`, `note`, UUID Idempotency-Key. Ни guestId, ни scope клиент
не задаёт. Проверяется владельческий доступ и живая сессия до/после блокировок.
Блокировки брони и заказа сериализуют жалобу с подтверждением получения.
Гостевая проекция выдаёт только status/note/answer, без внутренних исполнителей.

## Запуск и проверка

Следовать локальному запуску из [блока 7](CANVA_140_BLOCK_7_MARKET_CORE_WEB.md),
применив новую миграцию штатным migrator. Не сбрасывать `views_local`.
Самодостаточная проверка в одноразовом PostgreSQL 16:

```sh
npm run build
npm --prefix apps/api run build
VIEWS_GUEST_EMAIL_HTTP_PROOF=true VIEWS_GUEST_EMAIL_BROWSER_PROOF=true node scripts/cloud-core-tests.cjs
```

Проверки включают владение заказом, запрет закупщику отвечать, параллельный
повтор с одним ключом, запрет ранней жалобы, блокировку начисления, повтор
подтверждения, повторную жалобу после завершения и неизменность денег/остатков.
Браузер проходит guest → warehouse → guest через cookie BFF и реальный Core.

## Проверить вручную / ограничения

- Тексты и читаемость карточки гостя/склада в RU/UZ/EN, Light/Dark и узком экране.
- Ответ должен описывать реальное решение, а не обещать уже выполненный возврат.
- Склад видит очередь по объекту; отдельного фильтра жалоб/уведомлений ещё нет.
- Сроки претензий, ответственность за продукты и возвраты — проверить с юристом.
- Не вводить паспортные, платёжные и другие лишние личные данные в комментарий.
- Публичные веб/APK остаются 0.14.0-preview. Все 140 экранов ещё не завершены.

Вопросов для продолжения этого локального блока нет.
