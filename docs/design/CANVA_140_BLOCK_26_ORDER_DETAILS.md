# Блок26 — конкретный заказ из общего списка

Параллельная работа: отдельные карточки уборки, прачечной, V Market и консьержа;
один интегратор общего перехода/загрузки, отдельные inventory, browser proof и review.
Полная очередь всех140 ID: [CANVA_140_PARALLEL_QUEUE.md](CANVA_140_PARALLEL_QUEUE.md).
Использованы сохранённые Light/Dark WebP; новые онлайн-правки Canva не проверены.

Критерии приёмки, определённые до реализации:
1. Нажатие «Открыть заказ» перечитывает только нужную услугу по reservationId и cursor исходной страницы.
2. Показывается только выбранный ID, включая вторую страницу; отсутствие ID не подменяется соседним заказом.
3. Уборка: запрошенное время и собственная оценка; служебные заметки/идентификаторы не раскрываются.
4. Прачечная: опись/бирки/цены/срок возврата/претензия; V Market: состав/обращение/кредиты фолио;
   консьерж: переписка и серверный снимок SLA. Whitelist, bounded-поля, точные bigint; нет заявления об оплате/возврате.
5. Ошибка/offline/отзыв доступа очищают детали; поздние ответы игнорируются; повтор ручной.
6. Просмотр не создаёт команд/начислений; переход в направление сохраняет черновик; RU/UZ/EN × Light/Dark ×390px.
7. React StrictMode, смена target и unmount/remount не оставляют вечную загрузку и не восстанавливают старую карточку.

Схема и API существующие: migrations не добавлены; guest list endpoints повторно проверяют доступ к поездке.
Cursor — закладка, не авторизация. Нет нового GET по ID, сканирования истории или расширения прав.
Сумма заказа/оценка/расчёт прачечной не являются статусом оплаты. Кредит фолио не означает возврат денег.
Все четыре карточки read-only; изменение заказа и отправка сообщений остаются в действующих разделах услуг.
Без зависимостей, реальных партнёров, платежей и внешней почты. Постоянная views_local не используется.

Запуск: `npm run dev:local` — существующий disposable Core/PostgreSQL, synthetic данные.
Проверки: `npm test`, `npm run build`, API `npm run typecheck && npm run build`,
`node scripts/core-network-primitive-gate.mjs`, `node --test scripts/staff-mail.acceptance.cjs`;
`VIEWS_GUEST_EMAIL_HTTP_PROOF=true VIEWS_GUEST_EMAIL_BROWSER_PROOF=true node scripts/cloud-core-tests.cjs src/supply src/service-orders src/staff-auth`.
Для отдельного browser proof списка/деталей добавить `VIEWS_ORDER_LIST_BROWSER_ONLY=true`.
Development lifecycle: `node scripts/guest-order-detail-lifecycle.browser.cjs` (loopback, synthetic GET fixtures).

тогда показывается ошибка с возвратом к свежему списку. Прямая серверная выборка по ID — будущий срез.
