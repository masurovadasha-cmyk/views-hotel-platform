# Блок 16 — срок ответа консьержа

## Объём

Гость и сотрудник видят срок проверенного результата по поручению, статус
на момент чтения сервером, превышение срока и поздний ответ. Это развитие
SG-CO-001 / SD-CO-001; отдельная очередь нарушений SD-GN-003 и матрица
SA-GN-010 ещё не реализованы. Реестр остаётся 56 partial / 84 pending.

Используется существующая `concierge_requests.response_due_at` и `answered_at`
(миграция 0094 и последующие исправления). Новая миграция не требуется:
изменение добавляет вычисляемую проекцию к разрешённому чтению списка.
Результаты идемпотентных команд остаются неизменными.

## Правила

- 15 минут — существующая гипотеза пилота, не подтверждённое обещание сервиса.
- Срок относится к проверенному результату сотрудника, не первому сообщению.
- Назначение и промежуточная переписка срок не сбрасывают.
- Повторное сообщение гостя после ответа открывает новый цикл по существующим
  правилам. Закрытые/отменённые поручения не показывают текущую просрочку.
- Время оценки приходит с сервера; интерфейс подписывает часовой пояс устройства
  и обновление статуса при ручном обновлении. Фоновых уведомлений нет. Часы API и БД должны быть синхронизированы;
  вычисление в API имеет точность миллисекунд, отображение — секунд.
- Без сети переписка, профиль и формы скрываются; устаревший ответ запроса не
  должен восстанавливать данные. Неопределённая команда сохраняет прежний ключ
  для безопасного повтора после подключения.

## Запуск и проверки

```sh
npm run build
npm --prefix apps/api run build
npm test
VIEWS_GUEST_EMAIL_HTTP_PROOF=true VIEWS_GUEST_EMAIL_BROWSER_PROOF=true node scripts/cloud-core-tests.cjs
node scripts/core-network-primitive-gate.mjs
node --test scripts/staff-mail.acceptance.cjs
```

Интеграционный runner создаёт и удаляет отдельную PostgreSQL 16 на случайном
loopback-порту. Не выполнять fixture SQL на `views_local`.
Проверки на рабочем дереве поверх `2f64e79`:

- web build/typecheck: exit 0; 346 тестов в 67 файлах;
- API build/typecheck: exit 0; 553 теста в 93 файлах на отдельной PostgreSQL 16;
- четыре unit-теста границ SLA и семь интеграционных тестов консьержа включены;
- network primitive gate: 186 файлов, нет нарушений; mail acceptance: 15/15.

Первый браузерный прогон остановился на существующем тесте прачечной:
проверка `disabled` выполнялась до обработки события offline. Тест теперь ждёт
наблюдаемой блокировки кнопки; условие защиты и его проверка сохранены.
Второй прогон обнаружил удаление нового поля SLA гостевым BFF. Добавлена
строгая проекция разрешённых вложенных полей и тест удаления внутренних данных.
Повтор после исправления запускает профильные тесты через аргумент
`src/service-orders/concierge` того же disposable runner; без аргументов он
по-прежнему выполняет полную API-серию. HTTP/browser цепочка остаётся полной.

## Что проверить вручную

Срок и поздний ответ в RU/UZ/EN, Light/Dark, узком экране; время устройства;
обновление после возврата сети и неизвестного результата команды; отсутствие
доступа к чужой организации/объекту/назначенному диалогу.

## Ограничения

Нет расписания смен, пауз SLA, рабочего календаря, автоматической эскалации,
переназначения, штрафов или бонусов. Для них нужны отдельные политики и события.
Публичный Core не подключён. Этот блок не меняет опубликованный preview 0.15.

Профильный повтор: 16 тестов в трёх файлах, успешно. Браузер консьержа
подтвердил срок/просрочку/поздний ответ, очистку offline, отбрасывание
задержанного GET после reconnect, повтор неизвестной команды с тем же ключом,
RU/UZ/EN, мобильную ширину и Dark.

Полная HTTP/BFF/browser цепочка после исправлений завершилась с exit 0:
консьерж, уборка, прачечная, маркет, фолио, закупки, гостевые брони и вход через
loopback SMTP. Реальных писем и платежей не было.
