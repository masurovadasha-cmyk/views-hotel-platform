# Блок 17 — очередь просроченных поручений консьержа

## Что реализовано

Переключатель сотрудника «Все поручения / Просроченные поручения». Отдельная
SQL-выборка просрочек, а не фильтр текущих двух карточек. Guest API очереди нет.
Объём ограничен консьержем: это не общая матрица SLA всех услуг.

`GET /v1/service-orders/concierge/overdue?propertyId=UUID&cursor=UUID` возвращает
существующие карточки, `sla` и `nextCursor`. BFF выбирает объект из сессии;
произвольные property/time/query параметры клиента запрещены.

Миграция 0102 добавляет функцию SECURITY DEFINER с фиксированным search_path,
проверками сотрудника, организации, объекта и назначения. PUBLIC execute
отозван, существующей роли views_app предоставляется только вызов функции.
Таблицы и прежние RLS-политики не изменены. Добавлен частичный индекс активных
поручений. Используются существующие тестовые данные; новых боевых seed нет.

Состояния requested/working, срок строго раньше единого снимка времени БД.
Выборка до пагинации: максимум три записи (две карточки + признак продолжения).
UUID-порядок стабилен, но не означает «самые срочные первыми». Новые просрочки
до текущего курсора видны после обновления с первой страницы.
Ограниченный FOR SHARE защищает от конкурентного завершения при чтении карточек;
таймаут запроса 10 секунд. Это может кратко задержать конкурирующее действие.

Переключение сбрасывает страницу/курсор и инвалидирует старые ответы загрузки.
После действия сохраняется выбранная очередь. RU/UZ/EN, Light/Dark, offline.

## Запуск

```sh
npm run build
npm --prefix apps/api run build
npm test
VIEWS_GUEST_EMAIL_HTTP_PROOF=true VIEWS_GUEST_EMAIL_BROWSER_PROOF=true node scripts/cloud-core-tests.cjs
```

Последняя команда применяет миграции только к одноразовой PostgreSQL 16 на
случайном loopback-порту. Постоянная `views_local` не изменялась. Для обновления
действующей установки использовать её штатный migration runner после бэкапа.
Существующие cloud/windows runner находят 0102 автоматически, проверяют checksum
исторических миграций и сохраняют журнал применений.

## Ручная приёмка и ограничения

Проверить очередь под менеджером и консьержем, переключение во время загрузки,
переход страниц, ответ на поручение и исчезновение из просрочек, узкий экран,
три языка, Dark и восстановление связи. Проверить индекс/план на реальном объёме.

Автоматической эскалации, уведомлений руководителю, смен, SLA-пауз, бонусов и
штрафов нет. 15 минут остаются гипотезой пилота. Полная PDF-приёмка и очередь
нарушений для остальных услуг не завершены. Публичный preview 0.15 не менялся.

## Проверки текущего изменения

350 веб-тестов в 68 файлах; 554 API-теста в 93 файлах на отдельной PostgreSQL
с миграцией 0102. Network gate: 186 файлов, нарушений нет; mail acceptance 15/15.

дополнительной синтетической брони; добавлен явный cast. Приложение не менялось.
Профильный повтор и браузерная проверка фиксируются после завершения цепочки.

регрессионный тест отказа другим ролям/методам/суффиксам; 14 тестов guard прошли.

подтвердил несколько страниц очереди, отсутствие будущих/отменённых заявок
и заявки другого исполнителя, переключение обратно, RUUZEN/mobile/Dark,
offline и прежние сценарии консьержа.
