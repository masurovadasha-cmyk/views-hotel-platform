# Canva 140 — гостевая и рабочая прачечная

Базис: `6e529ae`. Расширяет проверенный Core 0075–0078 интерфейсами React и
cookie BFF. Это локальный функциональный блок, не полная визуальная приёмка
всех экранов Canva и не обновление публичного веба/APK 0.14.0-preview.

## Реализовано

- Гость, внутри своей поездки: каталог, оценка за вещь × количество, желаемое
  время забора, пожелания, отмена до получения вещей; опись с бирками, отдельными
  ценами и сроком возврата; явное согласование итоговой цены; отказ с ожиданием
  физического возврата; подтверждение получения и начисления в фолио.
- Управляющий/ресепшен с `reservation.manage`: отдельная очередь, код юнита,
  подтверждение получения, редактор 1–50 вещей с уникальными бирками, отправка
  описи, обработка, готовность, передача гостю, возврат без обработки.
- Русский, английский, узбекский; общие стили светлой/тёмной темы и мобильных
  форм. Суммы вводятся в основной единице валюты и переводятся в bigint без
  плавающей точки. У каждой описи серверная ревизия; старое согласие отклоняется.
- Потерянный ответ сохраняет тот же payload и ключ команды для ручного повтора.
  Пока результат неизвестен, переход из поездки заблокирован; предусмотрено
  предупреждение при закрытии страницы. Для разных услуг отдельные флаги ожидания.
- Статусы загрузки, пустой очереди, ошибки и отсутствия сети различаются.
  Каталог и очереди открываются по запросу, используют серверную пагинацию.

## Данные и границы

Миграция `0079_laundry_staff_location.sql` добавляет оператору код юнита через
связь с бронью в той же организации/объекте. Старые миграции неизменны.
Гостевой BFF не отдаёт код юнита, внутренние заметки и дополнительные поля описи.
Маршруты прачечной принимают только разрешённые параметры; propertyId рабочей
очереди задаётся сервером. POST требует cookie-сессию, origin/CSRF и UUID ключ.
Право housekeeping само по себе доступа к прачечной не даёт.

Финансовые правила не перенесены в браузер: до согласия нет service_order,
до подтверждения возврата нет начисления, общая книга фолио остаётся источником
истины. Новый отдельный платёжный механизм не создаётся.

## Запуск и проверка

В существующем checkout с установленными зависимостями, Node и Docker:

```sh
npm run build
npm --prefix apps/api run build
npm test
VIEWS_GUEST_EMAIL_HTTP_PROOF=true VIEWS_GUEST_EMAIL_BROWSER_PROOF=true node scripts/cloud-core-tests.cjs
node scripts/core-network-primitive-gate.mjs
node --test scripts/staff-mail.acceptance.cjs
```

Runner создаёт отдельный PostgreSQL 16, применяет миграции, использует только
синтетические аккаунты, запускает Core и BFF на loopback, затем удаляет только
свой контейнер. Постоянная `views_local` не используется. Флаги локального пилота
те же, что у уборки; включать публичный Core этой инструкцией нельзя.
Если порт 4173 занят существующим приложением, тест останавливается; чужой
сервер не завершать. Браузерная проверка: `scripts/laundry-browser-core-proof.cjs`.

## Риски и ручная приёмка

- SG-LA-005 (претензии, фото до/после), чат, QR-сканирование, назначение курьера,
  SLA, внешняя прачечная, автозакрытие и отдельная роль прачечной ещё не подключены.
- Доступна запись желаемого забора, а не гарантированная бронь мощности/окна.
  Время ввода и отображения явно обозначено как часовой пояс устройства.
- Команда повтора хранится в памяти вкладки. Принудительное закрытие её теряет;
  после входа сверить состояние с Core, не создавать новую заявку автоматически.
- Закрытое фолио отклонит начисление. Сотруднику нужна операционная сверка;
  приложение не открывает новый счёт обходным путём.
- Проверить вручную: опись на 50 вещей, длинные описания, крупный шрифт, экранный
  диктор, телефон сотрудника, обе темы, разные часовые пояса, отличие фактического
  количества от первоначальной оценки. Финальная визуальная сверка PDF остаётся.
- Условия ответственности за порчу и фискализация услуги — проверить с юристом
  и бухгалтером до реального запуска. Цены тестов не являются тарифами VIEWS.

Вопросов, блокирующих следующий локальный программный блок, нет.
