# Canva 140 — предложение замены от склада

Базис: `40b192a`. Расширены SG-MK-004, SD-MK-002 и SS-MK-001 переданного PDF.
Реализуется только собственный склад. Это не полная визуальная приёмка экранов.

## Процесс и допущения

На стадии `reserved`, до сборки, склад выбирает одну позицию заказа, другой
опубликованный товар того же объекта/валюты и причину (3–500 символов).
Количество заменяемой позиции сохраняется; товар не может уже присутствовать
в остальных строках корзины. Core рассчитывает весь предложенный состав по
текущим ценам — склад не вводит собственную сумму или скидку.

Гость видит причину, полный новый состав, итог и срок согласия. Исходная сумма
и исходный резерв пока не меняются. Новый товар не резервируется предложением;
наличие и цены заново проверяются при согласии. **15 минут — гипотеза для
калибровки**, а не обещанный отраслевой SLA. Продление или автоматическое согласие
отсутствуют. После истечения срока гость может отказаться, склад — отозвать и
создать новое предложение. Начало сборки блокируется до разрешения предложения,
включая истёкшее: склад должен явно отозвать его, прежде чем собирать исходное.

При согласии гость отдельно отмечает согласие со всем составом и суммой.
Создаётся связанный заказ через атомарный процесс блока 9. Любая ошибка цены,
остатка или проживания сохраняет старый заказ и ожидающее предложение.
Отказ/отзыв оставляют старый состав и резерв. Отмена исходного заказа отменяет
и предложение; самостоятельное изменение корзины гостем через API также
снимает старое предложение. Интерфейс при ожидании предлагает принять/отказать
или отменить заказ, без параллельного редактирования.

Сумма фолио, физический складской остаток и платежи не изменяются предложением,
отказом или согласием. Принятый новый заказ проходит обычную сборку и выдачу;
начисление — после подтверждения фактического получения.

## Миграции и API

- `0086_market_proposals_catalog.sql`: последнее предложение в
  `market_orders.proposal`, триггер блокировки сборки и отмены предложения,
  каталог опубликованных товаров для `stock.manage`, расширение ответов.
- `0087_market_proposal_actions.sql`: предложение, согласие, отказ, отзыв;
  живые сессии, владение бронью, scope, revision, idempotency, audit/outbox.
  Действующие миграции не переписаны. Прямые runtime-записи запрещены прежним RLS.
- Синтетический seed увеличен до 40 товаров исключительно для одноразовых тестов;
  он запрещён вне базы с маркером `VIEWS_DISPOSABLE_CORE_TEST`.

Существующие POST `.../market/:id/actions` используют UUID Idempotency-Key:

| Кто | action | Дополнительные поля к expectedRevision |
|---|---|---|
| Склад | propose_replacement | fromServiceId, toServiceId, note |
| Склад | withdraw_proposal | нет |
| Гость | accept_proposal | expectedTotalMinor (строка minor units) |
| Гость | decline_proposal | нет |

`GET /v1/service-orders/market/catalog?propertyId=...&cursor=...` требует действующей
складской сессии и права на объект. Cookie BFF подставляет объект из конфигурации,
не принимает propertyId клиента. Гостю передаются только публичные поля
предложения: статус, причина, сумма, срок, состав; внутренняя ревизия каталога
не выдаётся. История предложений остаётся в commands/audit/outbox; карточка
показывает только последнее предложение, не отдельный полный журнал переписки.

Блокировки брони и заказа сериализуют принятие с отзывом/отказом/сборкой.
При принятии используется существующий порядок складских блокировок блока 9.
Альтернативные товары не получают резерв до явного согласия гостя.

## Запуск

Локальные флаги и migrator описаны в [блоке 7](CANVA_140_BLOCK_7_MARKET_CORE_WEB.md).
Не выполнять reset/seed на постоянной `views_local`.

```sh
npm run build
npm --prefix apps/api run build
VIEWS_GUEST_EMAIL_HTTP_PROOF=true VIEWS_GUEST_EMAIL_BROWSER_PROOF=true node scripts/cloud-core-tests.cjs
```

## Что проверить вручную

- Склад предлагает одну позицию, гость видит весь итог, а не только доплату.
- Начало сборки недоступно при ожидающем предложении; отказ/отзыв возвращает его.
- Смена цены/нехватка запаса/истечение срока не отменяют исходный заказ.
- RU/UZ/EN, Light/Dark, узкий экран, длинные названия и причины.
- Необходимый товар доступен через страницы каталога; «Обновить» возвращает первую.
- После потери ответа повторить ту же команду; появляется ровно один преемник.

Ограничения: предложение только до сборки, без замены уже собранных товаров,
частичной выдачи, возврата денег/на склад и push-уведомлений. Расчёт компенсаций,
правила продуктов/фискализации — проверить с бухгалтером и юристом. Публичные
веб/APK остаются 0.14.0-preview, не включают этот локальный блок. Вопросов для
продолжения нет.

## Результаты проверки

11 октября 2026, изменённое дерево поверх `40b192a`: web typecheck/build,
329 тестов / 63 файла; API typecheck/build, 526 тестов / 89 файлов на
одноразовом PostgreSQL 16. Network gate: 180 файлов без нарушений;
mail acceptance: 15/15.

Первый браузерный прогон выявил неоднозначное доступное имя поля выбора товара;
добавлены aria-label для обоих списков. После этого web build/typecheck и
49 профильных Core-тестов + полный HTTP/BFF/browser runner прошли с exit 0.
Проверены истечение срока (синтетический перевод времени предложения), отказ,
повторное предложение, явное согласие, потеря ответа и один преемник, выдача,
обращение и одно начисление. На RU/UZ/EN при ширине 390 px переполнения нет.
Полная визуальная приёмка PDF и установка на физический Android не выполнялись.
