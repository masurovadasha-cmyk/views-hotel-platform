# Canva 140 — серверный процесс прачечной

Базис: `7c037fa`. Этот блок реализует Core/API для SG-LA-001–004 и операционных
очередей прачечной. Интерфейсы добавлены следующим [блоком 6](CANVA_140_BLOCK_6_LAUNDRY_WEB.md).
Фото и претензии SG-LA-005 ещё не реализованы;
это не полная приёмка экранов Canva.

## Решение

Существующий `service_orders` хранит неизменяемую принятую цену. Поэтому до
согласия гостя хранится заявка `laundry_intakes`: предварительная оценка и опись.
После согласия создаётся обычный заказ в общем реестре услуг. Начисление идёт в
общее фолио, события — в общий outbox, действия — в общий аудит и журнал
идемпотентности. Отдельного платёжного или финансового движка прачечной нет.

Предварительная оценка = базовая цена каталога за одну вещь × заявленное число
вещей. Она не является согласованной ценой. Сотрудник получает вещи, записывает
для каждой отдельную бирку, описание и цену; сумма вычисляется сервером. Гость
согласовывает точную сумму и ревизию описи. Цена и опись принятого заказа после
этого неизменны, даже если каталог изменился.

## Состояния и действия

| Исходное состояние | Кто / действие | Результат |
|---|---|---|
| — | Гость: заявка, 1–50 вещей, время забора, пожелания | requested; только оценка |
| requested | Оператор: receive | received; вещи получены |
| received / quoted | Оператор: quote, уникальные бирки, цены, срок возврата | quoted; новая ревизия |
| quoted | Гость: accept с ревизией и точной суммой | accepted; создан общий заказ |
| accepted | Оператор: wash | washing; общий заказ in_progress |
| washing | Оператор: ready | ready |
| ready | Оператор: deliver | delivered; ждём подтверждения гостя |
| delivered | Гость: confirm_receipt | closed; одно начисление, общий заказ completed |
| requested | Гость: cancel | cancelled; без начисления |
| quoted | Гость: reject | awaiting_return; вещи всё ещё у исполнителя |
| received / quoted / awaiting_return | Оператор: return_unprocessed | cancelled; зафиксирован возврат без обработки |

Начало обработки до согласия, повторное согласование после принятия и завершение
общего заказа без подтверждения/начисления запрещены. Отказ от цены не выдаётся
за физический возврат вещей. Времена передаются в UTC; забор/обещанный возврат
ограничены датами текущего проживания. Позднее исполнение не маскируется новой
датой: последующие SLA-уведомления должны использовать сохранённый срок.

## Миграции, права и API

- 0075: опция laundry в каталоге, таблица заявки, индексы по объекту и брони,
  составные FK, FORCE RLS, только чтение для управляющего; прямых runtime-записей нет.
- 0076: гостевой каталог, создание заявки, гостевая/операторская очередь с
  ограниченной пагинацией; проверка владения бронью и действующей сессии.
- 0077: блокировки бронь → заявка → фолио, повторная авторизация после ожидания,
  ревизии, идемпотентность, аудит/outbox в одной транзакции.
- 0078: запрет завершения заказа laundry без точного начисления и закрытой заявки.

Гостевые маршруты под `/v1/guest-identity/email/services`:

- `GET /laundry/catalog?reservationId=UUID[&cursor=UUID]`
- `GET /laundry?reservationId=UUID[&cursor=UUID]`
- `POST /laundry`: `reservationId`, `serviceId`, `expectedRevision`,
  `declaredCount`, `preferences`, `pickupAt`.
- `POST /laundry/:id/actions`: `action`, `expectedRevision`; для `accept`
  дополнительно `expectedTotalMinor` (строка с деньгами в минимальных единицах).

Операторские маршруты под `/v1/service-orders`:

- `GET /laundry?propertyId=UUID[&cursor=UUID]`
- `POST /laundry/:id/actions`: `action`, `expectedRevision`; для `quote`
  дополнительно `returnBy`, `items: [{tag, description, priceMinor}]`.

Для всех POST нужен UUID `Idempotency-Key`. Роль оператора в этом локальном
пилоте требует действующей staff-сессии и `reservation.manage` для объекта.
Горничная и закупщик не получают доступ автоматически. Отдельная роль сотрудника
прачечной и её интерфейс будут добавлены следующим блоком, без изменения
существующих назначений сотрудников. Гость не может подменить организацию/роль.

## Запуск и проверка

```sh
npm run build
npm test
npm --prefix apps/api run typecheck
npm --prefix apps/api run build
VIEWS_GUEST_EMAIL_HTTP_PROOF=true node scripts/cloud-core-tests.cjs
node scripts/core-network-primitive-gate.mjs
node --test scripts/staff-mail.acceptance.cjs
```

Runner использует временную PostgreSQL с маркером `VIEWS_DISPOSABLE_CORE_TEST`;
постоянная `views_local` не изменяется. Данные создаются тестовыми фабриками:
реальные каталоги/цены, сотрудники и брони не подменяются сид-данными.
Новые зависимости и конфигурация среды не нужны. API включается только при
существующих локальных test-флагах; production остаётся отключённым.

Проверено в рабочем дереве поверх базиса:

- API typecheck/build, веб build и 316 тестов.
- Полный Core: 505 тестов в 87 файлах. После добавления отдельного каталога —
  28 тестов сервисов и настоящий HTTP/Core/PostgreSQL прогон.
- Параллельные повторные заявки/подтверждения, гонка согласие–новая опись,
  точные bigint-суммы, сохранённая опись, RLS/чужой гость/чужая роль,
  закрытое фолио с полным откатом, неизменность заказа, возврат без обработки.
- HTTP: гостевая сессия, строгие поля, каталог, права управляющего, опись,
  согласие, обработка, получение гостем и ровно одно начисление.
- Network gate: 178 файлов, нарушений нет; mail acceptance: 15/15.

В первом HTTP fixture обнаружено неоднозначное приведение UUID к тексту в
синтетическом INSERT; исправлено, повторный HTTP-прогон прошёл. Реальные письма,
платежи, production и физический Android не запускались.

## Что проверить вручную / оставшиеся риски

1. Согласование изменённой суммы: старая ревизия/сумма должна отклоняться.
2. Полученные вещи нельзя отменить как ещё не забранные. Отказ требует возврата.
3. После потери ответа повторить прежний ключ; не создавать новое начисление.
4. Закрытое фолио оставляет заявку delivered и не завершает заказ; отдельное
   урегулирование долга/счёта пока не реализовано.
5. Подтверждение выдачи сейчас — действие оператора и затем гостя. Фото,
   QR/подписи, физическая сверка бирок, претензии и возмещение ущерба отсутствуют.
6. Нет SLA-таймеров, маршрутизации/назначения, экспресс-наценок, загрузки
   документов, внешней прачечной, SMS/push и автоматического закрытия без гостя.
7. Нет новых UI/BFF-маршрутов в веб/Android: следующий шаг — подключить эти API
   к гостевым экранам и рабочему месту прачечной. Публичный APK 0.14 не обновлялся.
8. Налоги, ответственность за вещи и правила компенсации — проверить с юристом
   и бухгалтером; демонстрационные цены Canva не считаются действующими тарифами.

Вопросов владельцу для продолжения внутренней разработки нет.
