# L4a — схема резерва по партиям, без включения приложения

## Критерии
- Одна активная привязка партии на позицию заказа, количество равно позиции.
- Заказ/товар/организация/объект связаны FK; партия проверяется по текущей версии ledger.
- Неизвестная и просроченная партия запрещены; применяется дата объекта.
- Общий item lock не позволяет двум запросам зарезервировать один остаток.
- Складское движение или сверка, нарушающие активный резерв, откатываются целиком.
- Терминальный статус заказа требует освобождения привязки в той же транзакции.
- Приложение не может записывать привязки: нет команды/API, write-policy или повышения прав.

## Схема
Migration0117 добавляет market_lot_reservations: FK к позиции заказа, товару, заказу и ledger;
частичный уникальный индекс активной позиции и индекс активных резервов партии.
RLS оставляет scoped чтение supply.read. INSERT guard SECURITY INVOKER допускает только владельца таблицы;
даже при широком GRANT runtime получает LOT_RESERVE_DISABLED до чтения партии.
Записи сохраняют происхождение; разрешено только однократное освобождение released_at, без удаления/реактивации.
Новый резерв требует текущий movement_id. Уже принятый резерв остаётся связан с маркировкой/датой
при последующих движениях; новый AFTER guard проверяет достаточность количества после ledger.
Отложенный constraint trigger проверяет освобождение при завершении/отмене заказа.

## Проверки и запуск
node scripts/cloud-core-tests.cjs src/supply src/service-orders src/staff-auth
Runner создаёт одноразовую PostgreSQL16; перед Core выполняет market-lot-reserve-proof.cjs
с двумя административными соединениями. Синтетические заказы и партии не попадают в dev-local.
Проверяются гонка (один победитель), дубликат, stale/unknown/expired/неверное количество,
ручное списание и сверка с откатом, откат освобождения, терминальный статус, RLS и запрет runtime-записи.
Сборки: npm run build; npm --prefix apps/api run build; npm --prefix apps/api run typecheck; npm test.
Также network primitive gate, staff-mail acceptance и checksum миграций.
Локальный запуск: npm run dev:local; миграция через штатный runner, persistent views_local не сбрасывать.

## Ограничения и ручная приёмка
Это фундамент БД, не пользовательское резервирование. Экран/API не добавлены намеренно.
Проверить отсутствие записывающей runtime-команды, неизменный общий SKU-резерв и возможность обычной выдачи без привязок.
Не создавать административные привязки в рабочей базе: существующие команды ещё не освобождают их.
Далее: аутентифицированная атомарная команда с идемпотентностью, аудитом и outbox; затем создание/замены/отмена/выдача,
инвентаризация и доступность каталога. Включать после проверки всех путей. FEFO, public web/APK не изменены.
