# L2f.1 — проверочный расчёт остатков партий

## Критерии приёмки
1. Только новая физическая сверка партий инициализирует расчёт; старые движения не получают выдуманное происхождение.
2. Приход с маркировкой, приход без маркировки, подтверждённая выдача и связанный возврат обновляют соответствующую партию; неизвестная явно null/null.
3. Сумма вычисленных партий совпадает с общим SKU. Выдача без партии или корректировка без распределения скрывают разбивку и требуют сверки.
4. Два поступления, повтор выдачи и откат после изменения расчёта не нарушают итог.
5. RLS/supply.read скрывает чужой объект; runtime не меняет расчёт напрямую.
6. API и экран RU/UZ/EN показывают проверочный статус, frontend отвергает несовпадающие суммы.

Migration0115: supply_lot_projections, scoped read policy и AFTER INSERT trigger всех физических движений. Используется существующая блокировка товара; обновлённый общий остаток доступен после BEFORE trigger. Подтверждённый снимок сбрасывает состояние, неоднозначное движение делает lots=null до следующего пересчёта. Расчёт и движение откатываются вместе.

Это read model для проверки модели L2, не разрешение выдачи или резерв по партиям. Прежняя проверка свежей сверки остаётся; новый расчёт её не заменяет. Автоматический FEFO не включён. Поступление после потери происхождения само по себе не восстанавливает разбивку. Источник истины — immutable движения и физические сверки.

Запуск: npm run dev:local; миграции штатным runner/checksum, без reset views_local. Проверка Core: node scripts/cloud-core-tests.cjs src/supply src/service-orders src/staff-auth. Целевой browser: VIEWS_SUPPLY_BROWSER_ONLY=true VIEWS_GUEST_EMAIL_HTTP_PROOF=true VIEWS_GUEST_EMAIL_BROWSER_PROOF=true с тем же runner.

Ручная проверка: сверка → подтверждённая выдача → приход → совпадающая сумма; выдача без партии → сообщение о пересчёте без чисел партий; новая сверка восстанавливает расчёт. Проверить три языка и отсутствие чужих объектов.

Риски/далее: JSON read model не предназначен для резервирования или массового поиска FEFO. До операционного включения нужен нормализованный ledger распределений, выбор партии по актуальному revision и покрытие конкурентных резервов. Публичные веб/APK и статус Canva не меняются.
