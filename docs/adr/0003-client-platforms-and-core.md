# ADR 0003 — стек Core и приложений

Дата: 8 октября 2026, Ташкент. Этап Б0.
Статус: рабочее архитектурное решение; существующее ядро подтверждено кодом,
новые приложения запланированы, но ещё не реализованы. Дополняет ADR 0001.

## Контекст

Один продукт должен обслуживать собственный фонд, маркетплейс и пять интерфейсов.
Первый фонд — 500 апартаментов в Ташкенте, Самарканде, Бухаре и Хиве. Сейчас
разработка ведётся владельцем через Codex, состав будущей команды ещё не нанят.
Уже работают NestJS/TypeScript, PostgreSQL 16, React/Vite и локальный Android
WebView. Переписывание этого ядра уничтожит проверенные ограничения и задержит
запуск. React/Vite не является Next.js, а WebView — React Native.

## Решение

- Сохраняем модульный монолит NestJS/TypeScript и PostgreSQL 16 — единственный
  источник истины. Доменные границы: identity, inventory, pricing, booking/stays,
  folio, ledger/payments, compliance, operations, messaging, marketplace.
- Публичные гостевые и хостовые страницы постепенно переносим в отдельное
  приложение Next.js внутри существующего репозитория. SEO-страницы могут
  использовать SSR/кеш; цена и доступность подтверждаются сервером при расчёте.
- CRM и админка остаются React. Общие типы API, локализация и дизайн-токены;
  платёжные/ценовые правила не копируются в клиент.
- Для новых мобильных приложений выбираем React Native с общими модулями
  гостя/персонала и отдельными точками входа/наборами разрешений. Это сокращает
  число языков в текущем TypeScript-проекте. Android — первый кандидат пилота;
  потребность iOS и состав устройств ещё нужно подтвердить.
- WebView сохраняется как существующий review-клиент до приёмки React Native,
  затем выводится по плану совместимости. Не выдаём его за готовый native-клиент.
- Outbox публикует задания в Redis/BullMQ после commit; PostgreSQL хранит
  авторитетные состояния и ключи дедупликации. Redis не решает доступность номера.
- S3-compatible storage для файлов; WebSocket для оперативных обновлений с
  восстановлением через REST. PostGIS/OpenSearch — только после измерения нужд
  поиска. Кеш не принимает решение о бронировании.
- Версионированный HTTP API/OpenAPI и версионированные события. SDK генерируются
  из контракта; один Core для веба, native и Telegram mini app.
- Docker/CI, feature flags, структурированные логи, метрики и error tracking
  без персональных документов. Инфраструктура в этом ADR не установлена/не куплена.

## Альтернативы и компромисс

Flutter добавляет Dart и второй набор общих моделей; выбираем React Native для
текущей команды TypeScript. Если выяснится, что команда специализируется на Flutter,
пересмотрим только mobile ADR, сохранив API. Микросервисы сейчас добавят распределённые
транзакции без измеренной необходимости; выделяем их позже по нагрузке/границам.

## Проверка решения

В этапах Б6/Б7: реальные устройства, плохая сеть, повтор после потери ответа,
обновление приложения, хранение сессии, мультиязычность, WCAG и экранный диктор.
В Б11: измерения p95/нагрузки/доступности. Выбор стека сам по себе не доказывает
300 мс, 100000 объектов или 99.9%.
