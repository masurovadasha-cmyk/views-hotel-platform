# L2f.3 — выдача V Market по актуальным версиям партий

## Критерии приёмки
1. Для каждой позиции сотрудник выбирает одну партию достаточного количества.
2. Staff API показывает текущие reconciled версии; гостевой API не раскрывает складские данные.
3. Устаревание любой выбранной версии откатывает весь заказ, включая ранее обработанные позиции.
4. Повтор одного ключа не дублирует выдачу; цена заказа остаётся неизменной.
5. После обновления партий интерфейс требует повторного выбора и подтверждения физической передачи.

Используются ledger и guards миграции0116; новых миграций, зависимостей и прав нет.
Staff API передаёт snapshotId/movementId и количество из неизменяемых строк текущего журнала.
Команда проверяет версии под блокировками; старый режим свежей сверки сохранён.
UI RU/UZ/EN: «Использовать актуальные версии партий». Изменение набора партий сбрасывает форму.

## Запуск и проверка
Локально: npm run dev:local. Только синтетическая среда; не сбрасывать persistent views_local.
Проверки: npm run build; npm --prefix apps/api run typecheck; npm --prefix apps/api run build; npm test.
Связанный прогон: VIEWS_GUEST_EMAIL_HTTP_PROOF=true VIEWS_GUEST_EMAIL_BROWSER_PROOF=true node scripts/cloud-core-tests.cjs src/supply src/service-orders src/staff-auth.
Также node scripts/core-network-primitive-gate.mjs и node --test scripts/staff-mail.acceptance.cjs.

Вручную: готовый заказ → выбрать партии → изменить склад в другом окне → попытаться выдать.
Ожидается отказ без частичного списания; обновить, выбрать заново и подтвердить передачу.
Проверить три языка, неизвестную дату, отказ для просроченной партии и изоляцию объектов.

Ограничения: одна партия на позицию, ручной выбор; FEFO, резерв по партиям и автоматическая выдача не включены.
Просроченная партия может отображаться в выборе, но сервер запрещает её выдачу.
Публичные веб/APK и статус Canva не изменяются; весь маркет ещё не завершён.
