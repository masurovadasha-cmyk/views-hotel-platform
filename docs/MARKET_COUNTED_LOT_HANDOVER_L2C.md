# L2c — выдача V Market из сверенных партий

## Критерии приёмки
1. Только сотрудник выбирает одну партию для каждой позиции готового заказа.
2. Снимок относится к нужному товару и объекту, актуален, количества достаточно.
3. Ошибка любой позиции откатывает всю выдачу и освобождение резервов.
4. Повтор команды не дублирует движения; изменение выбора с тем же ключом отклоняется.
5. Цена не меняется; гостевой API не раскрывает сведения о партиях склада.

## Реализация и запуск
Migration0112 расширяет существующую функцию выдачи; guard0111 проверяет снимок под блокировкой товара. API нормализует выбор; staff list возвращает доступные снимки; экран поддерживает RU/UZ/EN. Запуск: `npm run dev:local`, штатные миграции с checksum. Не сбрасывать views_local.

Проверки: `npm run build`, `npm test`, `npm --prefix apps/api run typecheck`, `npm --prefix apps/api run build`.
Интеграция в одноразовой PostgreSQL16: `VIEWS_GUEST_EMAIL_HTTP_PROOF=true VIEWS_GUEST_EMAIL_BROWSER_PROOF=true node scripts/cloud-core-tests.cjs src/supply src/service-orders src/staff-auth`.

## Риски и ручная проверка
- Проверить все три языка, неизвестную партию и невозможность подтверждения неполного выбора.
- Изменить склад после загрузки: выдача должна отклониться без частичных движений; обновить данные и пересчитать товар.
- После выдачи снимок устаревает. Это происхождение выданного товара, не живой баланс партий, FEFO или блокировка просрочки.
- Старый режим без распределения сохранён явно. Возвраты и многопартийная выдача — следующие срезы.
- Публичные веб/APK не публиковались; новых зависимостей и разрешений нет.
