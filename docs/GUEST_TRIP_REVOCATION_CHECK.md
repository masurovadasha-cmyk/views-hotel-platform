# Отзыв доступа к поездке — браузерная проверка, 14 октября 2026

Срез исправляет проверку, а не бизнес-логику. В сценарии отмены после reload тест нажимал View trip и сразу проверял отсутствие кнопки отмены. Это проходило и до загрузки карточки. Затем отзыв доступа мог опередить detail-запрос: правильный404 менял Refresh trips на Try again, и старый тест зависал на поиске Refresh trips. Повтор исходного прогона прошёл — сбой зависит от порядка ответов.

## Критерии
- После reload дожидаться реальной карточки отменённой брони, затем проверять отсутствие повторной отмены.
- Удержать новый detail-запрос на сетевом барьере и отозвать доступ до его исполнения.
- Во время загрузки старая карточка скрыта; после404 нет карточки и списка из кэша.
- Повтор ранее успешной отмены после отзыва получает404.
- Ручной Try again возвращает пустой список; общий browser suite продолжает работу.

Реализация: scripts/guest-cancellation-browser-proof.cjs. Барьер разрешает реальный запрос к Core после отзыва, не подменяет ответ API и не использует sleep. Существующие проверки CSRF, точных денежных сумм, потери ответа, replay, освобождения периода и отсутствия сотруднических прав сохранены. Миграций, новых зависимостей и изменений приложения нет.

## Запуск
Сначала завершить сборки, затем запускать браузер: fixture читает dist с диска, пересборка одновременно с reload может удалить обслуживаемые файлы.
```sh
npm run build
npm --prefix apps/api run build
VIEWS_GUEST_EMAIL_HTTP_PROOF=true VIEWS_GUEST_EMAIL_BROWSER_PROOF=true node scripts/cloud-core-tests.cjs src/supply src/service-orders
```
Одноразовая PostgreSQL16 и synthetic guest/staff; реальная почта и платежи отключены. Не использовать persistent views_local для fixtures.

Ручная проверка: открыть отменённую поездку; убедиться, что повторная отмена отсутствует; отозвать привязку аккаунта; повторно открыть поездку и обновить после сообщения об отсутствии доступа. Этот срез не реализует push-отзыв уже открытой карточки без нового запроса.
