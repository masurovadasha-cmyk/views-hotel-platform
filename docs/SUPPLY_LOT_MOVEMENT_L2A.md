# L2a — журнал подготовки движений к распределению по партиям

14 октября 2026. Первый небольшой срез L2, не завершённый учёт остатков партий.

## Критерии приёмки
- Каждое новое физическое движение создаёт ровно одну запись журнала в той же транзакции.
- Охвачены приёмка, ручная выдача, выдача V Market, инвентаризация и возврат после инспекции.
- Откат команды откатывает журнал; replay не дублирует запись и не меняет остаток повторно.
- Доступ на чтение ограничен supply.read и объектом; runtime не может вставлять/переписывать журнал вручную.
- История склада показывает статус подготовки на RU/UZ/EN, не выдавая его за фактическое распределение товара.

Migration0110 создаёт supply_lot_movement_intake с PK/FK movement_id и AFTER INSERT триггером на supply_movements. Статус определяется только по существующей неизменяемой приёмке/сверке в том же scope. FORCE RLS, read-only policy, append-only guard; триггерная функция имеет фиксированный search_path и недоступна для прямого вызова PUBLIC. Новых прав сотрудникам и зависимостей нет. Чтение соединяется по PK; отдельный индекс для очереди не нужен, поскольку фоновой обработки нет.

Статусы: receipt_lot_recorded — сведения о партии прихода записаны; snapshot_recorded — физическая сверка записана; allocation_pending — распределение ещё требуется. Старые движения не переносятся автоматически, отсутствие записи показывается как not_tracked. Количества, виды, документы и время берутся из исходного движения; копия финансового/складского регистра не создаётся.

Это журнал входящих движений, не распределение: нет живых остатков партий, FEFO, блокировки просрочки и автоматического приписывания партии возврату. Сохранение кода партии поступления не доказывает партию выданного товара. Ни один статус не означает «распределено». Общий остаток, резерв, финансовые начисления и API команд не меняются. Новый триггер требует штатного владельца миграций с правами служебных триггеров; runtime RLS не отключать.
