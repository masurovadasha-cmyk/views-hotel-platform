# Локальный экран SMS и тестовой оплаты

После `npm run build` и `npm --prefix apps/api run build`:
`node scripts/cloud-core-tests.cjs --dev-local --demo-sms`.
Откройте напечатанный webPort: http://127.0.0.1:PORT/?entry=sms-demo.
Это адрес внутри облачной машины, не публичная ссылка для телефона.

Сценарий: синтетический телефон → код из локальной консоли → свои поездки →
тестовая оплата → подтверждение. Сотрудник заранее выдаёт персональное предложение (quote) этому SMS-аккаунту.
Гость вводит его ID, видит даты/строки/итог и создаёт hold кнопкой.
Поиска объектов и самостоятельного расчёта по датам пока нет.

Токен только в памяти React, без localStorage/sessionStorage/cookies. Reload
потребует повторного входа. Платёж идемпотентен по reservationId; при потере
ответа повторяется оплата той же брони. Двойное нажатие блокируется сразу.
Прокси доступен только local/test/demo, same-origin, с custom header и allowlist;
actor/staff заголовки не передаются. Public review/android исключают вход в экран.

Критерии/проверки: точные bigint суммы UZS/USD/EUR, нет токена в storage,
offline не отправляет оплату, lost reply повторяет ту же бронь, confirmation
обновляет поездки; gateway отклоняет чужой Origin и неподдерживаемые маршруты.
`node --test scripts/guest-sms-gateway.acceptance.cjs`
`node scripts/sms-payment-screen.browser.cjs`
`node scripts/cloud-core-tests.cjs --dev-local --smoke --demo-sms`

Полный локальный browser→gateway→Core→PostgreSQL тест:
`node scripts/cloud-core-tests.cjs --dev-local --smoke --demo-sms --browser-smoke`
Требует Chromium `/usr/bin/chromium` и собранные web/API. Использует только
маркированную одноразовую БД. SMS-вход, оплата и выход выполняются браузером;
quote выдаётся фикстурой; hold создаётся мышкой, с потерей первого ответа
и повтором с тем же Idempotency-Key. Поиск/выдача предложения ещё вне UI.
Проверяет offline, потерю ответа после commit, повтор без второго capture,
баланс проводок, подтверждённую занятость, отзыв сессии и запрет чужой оплаты.
Проверяется отсутствие горизонтального переполнения при390px.
Отдельный `sms-payment-screen.browser.cjs` сохраняет mock Core для быстрых UI-проверок.
UI пока RU; Next shell, UZ/EN, полный поиск/бронь и late refund ещё нужны.
Миграции/платёжная логика не менялись. APK подпись и public web не обновлялись.

Ключ hold хранится в памяти до завершения; при неизвестном результате повторяйте
ту же кнопку без перезагрузки. Сервер проверяет доступность/срок предложения.
Показан серверный срок оплаты; живого обратного отсчёта пока нет.

Срок цены обновляется каждую секунду. Истёкшее предложение блокирует первый
запрос hold; уже отправленный запрос можно повторить с тем же ключом независимо
от таймера. До отправки доступно «Другое предложение». Клиентские часы не заменяют
серверную проверку. Это таймер quote, не таймер оплаты существующей брони.
