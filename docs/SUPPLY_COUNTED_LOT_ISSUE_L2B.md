# L2b — ручная выдача из сверенной партии

14 октября 2026. Законченный сценарий ручной выдачи одной партии; общий L2 ещё не завершён.

## Приёмка
- В форме выдачи можно выбрать одну партию из свежей физической сверки L1; старая выдача без распределения сохраняется.
- Сервер проверяет, что сверка относится к тому же SKU/организации/объекту, её revision актуальна, а количество партии достаточно.
- Выбранные код/годность должны точно совпадать со строкой сверки; неизвестное происхождение записывается явно как null/null.
- Команда атомарно уменьшает общий остаток и сохраняет provenance; повтор того же ключа не выдаёт товар снова, изменение содержимого конфликтует.
- Две независимые выдачи по одной сверке: только одна проходит. Следующее физическое движение требует новой сверки.
- История показывает выбранную партию и статус выдачи, RU/UZ/EN. Общий режим живых остатков партий не включён.

Migration0111 добавляет immutable lot_allocation к supply_movements и generated FK lot_snapshot_id → supply_stocktakes. BEFORE INSERT guard блокирует тот же item, что существующие движения, проверяет тип issue, source scope, revision и количество. Все существующие правила доступного остатка/резервов и actor/RLS продолжают действовать. INSERT нельзя обойти прямой записью JSON с ложной партией. Функция имеет фиксированный search_path, прямой EXECUTE для PUBLIC отозван. Старые записи остаются NULL, новых прав и зависимостей нет.

API issue получает необязательный lotAllocation={snapshotId,lotCode,expiresOn}; количество берётся из самой выдачи. SnapshotId выдаётся scoped stock read. История читает provenance и показывает lot_issued; исходная intake-запись L2a остаётся неизменяемым свидетельством поступления движения в журнал, а не обновляемой очередью.

## Ограничения
Это ручной выбор на основании физической сверки, не сканирование упаковки. Неизвестная партия не становится известной автоматически. Одна партия на команду; несколько партий требуют отдельных выдач и повторных сверок. После частичной выдачи остаток партии не вычисляется и не публикуется как подтверждённый живой остаток. Выдачи V Market, возвраты и автоматическое распределение ещё не подключены. Просроченная дата не блокируется; FEFO и правила допуска относятся к L3. Обычная выдача без партии остаётся доступной с явным статусом ожидания распределения.
