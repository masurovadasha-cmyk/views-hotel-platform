# L2f.2 — версии распределения и ручная выдача текущей партии

## Критерии приёмки
1. Каждое новое движение получает immutable запись журнала; при согласованном распределении — нормализованные строки quantity_after с суммой, равной SKU.
2. Неинициализированное/нарушенное распределение записано явно, партии не восстанавливаются предположительно.
3. Ручная выдача привязана к snapshotId и movementId текущей версии; сервер под item lock проверяет версию и количество в журнале.
4. Два разных запроса к одной версии дают одного победителя; replay одного ключа не создаёт вторую выдачу.
5. Старый режим свежей сверки сохранён; неизвестное происхождение отключает новый режим до пересчёта.
6. RLS/supply.read изолирует журнал; записи и строки неизменяемы, runtime не записывает их напрямую.

Migration0116: supply_lot_ledger и supply_lot_ledger_lines, сумма строк проверяется при записи под общей блокировкой товара. Это журнал распределения **после** каждого движения, не отдельная финансовая книга и не расчёт налогов. Исторические движения не дописываются. Версия записывается после projection; обе части откатываются вместе с движением.

Новая форма «Выдать по актуальному остатку партии» RU/UZ/EN требует явного выбора партии. quantity_after берётся из неизменяемых строк журнала; projection служит указателем актуальной версии, а не доверенным клиентским остатком. Старые запросы без movementId по-прежнему требуют свежую физическую сверку. Срок годности и общий резерв V Market проверяются прежними DB guards.

Ручная проверка: сверка → выдача → устаревший снимок → новый режим → следующая выдача без пересчёта; два открытых окна должны конфликтовать по версии. Без выбора партии подтверждение недоступно; движение без партии отключает новый режим. Проверить RU/UZ/EN, expiry и чужой объект.
