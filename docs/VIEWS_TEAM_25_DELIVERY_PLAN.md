# План для команды из 25 разработчиков

Оценка от начала работы полностью укомплектованной команды, не обещание даты.
25 человек — план реальной команды; в текущей среде доступны максимум 7
одновременных агентов, включая ведущего. Текущую задачу выполняют ведущий,
разработчик API, разработчик интерфейса и независимый проверяющий.

## Организация

Пять групп по пять разработчиков с владельцем технической области:

1. Бронирование, доступность, цены, платежи и финансовый учёт.
2. PMS, сотрудники, housekeeping, склад и закупки.
3. Гостевые веб/мобильные интерфейсы, доступность и локализация.
4. Услуги, хосты, партнёры и их кабинеты.
5. Платформа, безопасность, эксплуатация и внешние интеграции.

Группы работают по согласованным API и миграциям; общий review для финансов,
прав и данных. Единые интеграционные сборки. Примерно 20% мощности резервируется
на интеграцию, исправления и надёжность; первые 2–4 недели включают адаптацию.
Дополнительно нужны QA, продукт/дизайн, управляющий, бухгалтер и юрист.

## Сроки и условия

| Результат | Ориентир от старта |
|---|---|
| Аудит кода/140 экранов, согласованные критерии и план | 2–3 недели |
| Рабочие основные сценарии собственного фонда в тестовом окружении | 3–4 месяца |
| Пилот, восстановление/нагрузка/безопасность, запуск 500 апартаментов по волнам | 5–6 месяцев |
| Маркетплейс с хостами и согласованной схемой выплат | 7–9 месяцев |
| Широкий набор агрегаторов, каналы, новые страны | 9–15+ месяцев |

Четыре месяца до запуска — оптимистичный сценарий ограниченного собственного
фонда при готовых интеграциях. Базовый план — 5–6 месяцев. Все 140 макетов не
равны всей платформе: каждый требует функциональной и визуальной приёмки.
Внешние страны и новые интеграции не имеют единой конечной даты без фиксированного
перечня. Для каждой страны нужен отдельный перечень готовности.

Договоры провайдеров, юридическая модель выплат, размещение документов,
фискализация и E-mehmon — внешние зависимости. Дополнительные разработчики не
устраняют ожидание их согласования. Отсутствие ключей не блокирует внутренние
процессы и контрактные тесты, но блокирует приёмку реальных интеграций.

Уточнить оценку после аудита и двух спринтов по фактической скорости команды.
Добавлять разработчиков по измеренному узкому месту, не автоматически.
