# Срез31 — доступ при повторной отправке отзыва об уборке

Продолжение: [срез32 — внешние переходы при неподтверждённой команде](GUEST_OUTER_PENDING_GUARD_32.md); ниже сохранены результаты среза31.

Критерии приёмки:
1. Повтор после ожидания ключа возвращает сохранённый результат только при действующей сессии и владении бронью.
2. Logout, отвязка профиля и смена основного гостя во время ожидания дают отказ без результата отзыва.
3. Новая команда и replay проверяют сессию после существующих блокировок брони/профиля/заказа/задачи.
4. При отказе отзыв, заказ, задача, фолио, audit/outbox не меняются; новых прав runtime нет.
5. Разрешённый повтор после выезда/изменения каталога сохраняет исходную квитанцию;
   изменённое тело с тем же ключом остаётся конфликтом.
6. Гонки подтверждаются pg_locks и PID блокирующего соединения, с ограниченными таймаутами.

Решение: migration0122 заменяет только app.guest_service_feedback из SQL0074.
Возврат replay переносится после прежних блокировок и текущей проверки сессии,
до проверки завершённости уборки/существования отзыва. Правила единственного отзыва,
атомарность, сигнатура, payload, порядок блокировок, ACL и финансовые эффекты сохраняются.
Это частная оценка выполненной услуги, не публичный двусторонний отзыв о проживании.
Новых таблиц, индексов, зависимостей или прав нет; применённые миграции не переписываются.

Запуск synthetic-среды: `npm run dev:local`.
Проверки: `npm test`, `npm run build`; API `npm run typecheck && npm run build`;
`node scripts/core-network-primitive-gate.mjs`, `node --test scripts/staff-mail.acceptance.cjs`.
Интеграционная и браузерная проверка:
`VIEWS_CLEANING_BROWSER_ONLY=true VIEWS_GUEST_EMAIL_HTTP_PROOF=true VIEWS_GUEST_EMAIL_BROWSER_PROOF=true node scripts/cloud-core-tests.cjs src/supply src/service-orders src/staff-auth`.
Новый focused flag использует прежний сценарий уборки после настоящего локального входа;
default full chain не изменён. Общая браузерная цепочка в этом срезе не повторялась.

Что проверить вручную: инспекция уборки → отправка оценки → потеря ответа → повтор
той же команды; после logout/смены владельца отказ, после выезда доступная история сохраняется.
Отзыв не добавляет начисления и не отправляет деньги. Таймаут требует ручной сверки/повтора.
READ COMMITTED допускает завершение разрешённого запроса, если отзыв доступа закоммичен
после последней проверки. Глобальной атомарности logout со всеми запросами не обещаем.
Проверки только на disposable PostgreSQL; публичные web/Cloudflare/APK не меняются.
