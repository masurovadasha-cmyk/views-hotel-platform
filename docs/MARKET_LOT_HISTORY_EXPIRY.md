# L2e / L3a — история возврата и согласованная годность

## Критерии приёмки
- История склада показывает исходную партию и ID выдачи для подтверждённого возврата; старое происхождение не выдумывается.
- Доступ остаётся через supply.read и RLS; frontend отвергает повреждённую ссылку/дату и сведения возврата на выдаче.
- Согласованная владельцем дата действует до конца дня объекта. Тест фиксирует границу 23:59:59 / 00:00 Asia/Tashkent.
- DB-trigger запрещает выбранную просроченную партию при выдаче и подтверждённом возврате; откат сохраняет остаток/revision.
- Неизвестная дата не допускается helper для автоматического решения; существующие ручные операции остаются, автоматического распределения нет.

Migration0114 добавляет чистую функцию проверки календарной даты и trigger движений; сведения истории читаются из immutable ссылки0113, отдельная миграция чтения не нужна. Цены и проводки не меняются. Неизвестное происхождение не становится известным от нового отображения.

Запуск `npm run dev:local`; миграции штатным runner, без reset views_local. Проверки: web/API build/typecheck, npm test, disposable Core supply/service-orders/staff-auth; connected browser проверяет историю склада после возврата. Ручная проверка: RU/UZ/EN, партия/дата/исходная выдача, неизвестная партия, истекшая дата и повтор после отклонения.

Ограничения: guard проверяет записанную партию. Ручная операция без распределения по партиям требует проверки сотрудником и не доказывает годность. Живые остатки, FEFO, резерв по партиям и фото остаются открыты; это не завершение всего V Market. Публичные веб/APK не обновлены.
