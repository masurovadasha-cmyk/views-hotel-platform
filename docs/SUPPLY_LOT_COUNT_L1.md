# L1 — физическая сверка партий, 14 октября 2026

Сотрудник склада выбирает товар в существующей форме инвентаризации и включает «Записать сверку партий». Заполняет1–20 строк: код/годность/количество, либо явно неизвестная партия. Сумма строк должна совпадать с физическим количеством и текущим общим остатком. Если общий остаток неверен, сначала проводится обычная инвентаризация, затем отдельная сверка партий.

## Критерии и реализация
- Migration0109: nullable lot_counts в immutable supply_stocktakes; CHECK проверяет структуру, даты, дубликаты и сумму; индекс последнего снимка по revision. Старые записи остаются NULL.
- Используются существующие FORCE RLS, stock.manage, scope, actor guard, блокировка item, audit/outbox и идемпотентная команда. Новых прав и зависимостей нет.
- Только нулевая корректировка: создаётся существующее складское движение adjustment0, которое увеличивает revision. Общий и зарезервированный остатки не меняются.
- Снимок актуален на момент чтения только при balance.revision=expected_revision+1. Любое последующее движение, в том числе нулевая инвентаризация, делает его устаревшим. Изменение резерва без физического движения не меняет физический снимок.
- Конкурирующие подтверждения с разными ключами: один победитель; тот же ключ возвращает прежний результат без нового движения. Изменение состава при том же ключе запрещено.
- API preview/confirm сохраняют прежний контракт без lots; браузер проверяет совпадение распределения в preview и структуру снимка.
- Экран показывает дату сверки, известные/неизвестные партии и статус «Актуально на момент проверки»/«Устарело: пересчитайте партии» на RU/UZ/EN.

Это не живой остаток партий, не FEFO и не блокировка просрочки. Старые поступления не превращаются автоматически в остатки. Сведения вводятся после физического осмотра. Годность — календарная дата, не разрешение продавать товар. Событийного push-обновления статуса нет: перечитать склад вручную.
