# L2d — возврат в подтверждённую партию выдачи

## Приёмка
1. В инспекции сотрудник видит сохранённую партию выдачи и явно подтверждает совпадение маркировки.
2. Источник назначает сервер; заказ, товар, организация и объект совпадают. Источник без партии запрещён.
3. Ссылка и увеличение остатка атомарны; повтор команды не создаёт второго движения.
4. Неудачная привязка оставляет возврат в карантине; роли и обязательный чек-лист сохранены.
5. Гостевые начисления не меняются, складские сведения остаются staff-only.

Migration0113 добавляет immutable FK return_source_issue_id к supply_movements и проверяющий trigger. Возврат с sameIssuedLot=true ссылается на исходное движение с lot_allocation; старый возврат без партии доступен. Не требуется свежий снимок: это ссылка на факт выдачи, а не повторное списание из прежней сверки. Все движения по-прежнему устаревают текущую сверку.

Запуск: `npm run dev:local`; не сбрасывать views_local. Миграции применяет штатный runner с checksum.
Проверки: `npm run build`, `npm test`, API typecheck/build; `VIEWS_GUEST_EMAIL_HTTP_PROOF=true VIEWS_GUEST_EMAIL_BROWSER_PROOF=true node scripts/cloud-core-tests.cjs src/supply src/service-orders src/staff-auth` использует одноразовую PostgreSQL16.

Ручная проверка: выдача из партии → приём возврата в карантин → инспекция → сравнение маркировки → явное подтверждение → возврат на склад. Проверить режим без партии, три языка, отсутствие складских данных у гостя, неизменный счёт.
Риски: подтверждение сотрудника не доказывает физическое происхождение товара; при несовпадении маркировки не включать привязку. Живые остатки партий, FEFO, многопартийная выдача и поиск происхождения старых движений не реализованы. Автоматического денежного возврата нет. Публичные веб/APK не публикуются.
