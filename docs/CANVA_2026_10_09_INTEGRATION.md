## Как согласованы различия между документами

Гостевой документ показывает светлые тёплые поверхности, спокойные фотографии
апартаментов и золотой акцент. Staff CRM визуально оформлен как чёрно-белая
презентация; при этом текст страницы Dark Mode прямо описывает indigo/blue
operational accents. Design System иллюстрирует тёмную красноакцентную тему.
Эти источники не образуют один непротиворечивый набор готовых дизайн-токенов.

Для VIEWS принято следующее решение реализации:

- Гостевой интерфейс — ivory/gold, крупные фотографии и ясная последовательность
  поиска, просмотра и подготовки брони.
- Сотрудники — нейтральные рабочие поверхности и indigo-акцент; роли, состояния
  очередей, задачи и действия визуально различимы.
- Красный — смысловой цвет ошибок и опасных действий; он не используется
  автоматически как основной цвет всей платформы только из-за презентации Design System.
- Общими остаются правила фокуса, состояний форм, радиусов, интервалов, мобильной
  компоновки и светлой/тёмной темы.

Конкретные CSS-значения — инженерные значения VIEWS, а не якобы извлечённые
HEX/px/font tokens Canva. Доступные слайды не содержат полного точного token export.
Точно повторить сетку реального приложения по перспективным изображениям телефона
на презентации также нельзя: геометрию адаптируют к размеру браузера.

Guest Navigation содержит пять разделов, а слайд Guest Components — четыре.
Выбран полный сценарий из пяти вкладок: Explore, Bookings, Services, Messages,
Profile. Это явное решение, а не утверждение, что изображения идентичны.

## Границы готовности

Публичный сайт и APK остаются `static-demo`. В нём допустимы локальные фильтры,
избранное, смена вкладок, просмотр карточек, форм и демонстрационные изменения
очереди. Они не должны маскироваться под реальные операции.

Для рабочего Core уже существуют отдельные локальные процессы авторизации,
поездок, привязки брони, ограниченной отмены, ресепшн, уборки, фолио и снабжения.
Этот дизайн-блок не расширяет их финансовые полномочия и не переносит legacy
`Live*`/`/api` в PostgreSQL автоматически. Он не включает платежных провайдеров,
почту, E-mehmon, цифровые ключи, сообщения или фото-загрузку.

Не подтверждены полная карта и цены, полный guest checkout, realtime inbox,
автоматические SLA-эскалации, обязательные housekeeping checklist/photo/inspection,
ремонт с материалами, единый Stay Card всех доменов, полная Guest 360 и offline
синхронизация. Подробная привязка пробелов к страницам есть в матрице.

AED, EUR/USD суммы, sample KPI, имена, телефон и домены на слайдах — примеры
презентации. Они не задают тарифы, туристический сбор, контакт поддержки,
фактическую загрузку или подтверждённую личность пользователя VIEWS.

## Проверки перед фиксацией и публикацией

Команды из корня репозитория:

```sh
npm run typecheck
npm test
npm run build
node scripts/staff-role-entry.browser.cjs
node scripts/guest-link-staff-browser-proof.cjs
node scripts/legacy-staff-localization.browser.cjs
```

Для новой межэкранной проверки используется `scripts/canva-design.browser.cjs`,
подготавливаемый в этом же блоке. Выполнять его после завершения компонентов и
обычной сборки; не считать наличие скрипта доказательством прогона.

Публичные проверки выполняются последовательно:

```sh
npm run build:review
node scripts/access-portal.browser.cjs
npm run build:android
VIEWS_ACCESS_BUILD=dist-android node scripts/access-portal.browser.cjs
node scripts/android-review-web-proof.cjs
```

Для Core-интеграционных проверок затем заново собрать обычный `dist` и использовать
существующий одноразовый harness. Не запускать разные сборки одновременно в один
каталог. Не применять миграции и тестовые сиды к постоянной `views_local` ради
визуального тестирования.

На рабочем дереве относительно `64a9731` прошли frontend307/56, typecheck,
normal/review builds, Canva browser214layout и54guestcontrast samples
(минимум5.15:1), guest/legacy staff HTTP-fixture regression, portal и9role entries.
Исправлены несогласованные pins фильтров, контраст темы, фокус/возврат из drawer.
Последующая узкая правка подписей календаря включена в финальный release-прогон;
его полный результат и чистый SHA фиксируются в GitHub Release notes.
Публичная доставка требует отдельной сверки release.json и скачанного APK;
дата анализа и локальный build не являются подтверждением публикации.

## Ручная визуальная и сценарная приёмка

1. Сопоставить G1–G9 с реальными экранными состояниями, а не с изображением
   телефона вокруг них. Проверить карточку, amenities, результаты без совпадений,
   изменения фильтров, все пять вкладок и обозначение недоступной цены.
2. Проверить последовательность бронирования и черновик услуги. Черновик должен
   показывать выбранную категорию и введённые данные, явно сообщать, что ничего
   не отправлено; обновление страницы не должно притворяться серверным сохранением.
3. Проверить CRM очереди, фильтры, поиск без результатов, разрешённые действия и
   детали задачи. Неверные переходы не должны выглядеть доступными. Проверить
   сохранение смысла demo/неподключённого состояния после каждого действия.
4. Пройти RU/UZ/EN в светлой и тёмной теме при ширинах 360, 768 и 1440; добавить
   длинные названия, числовые значения и масштаб текста. Проверить горизонтальный
   overflow, читаемость secondary-текста и визуальное различие статусов.
5. Пройти Tab/Shift+Tab/Enter/Escape: видимый фокус, открытие/закрытие деталей,
   возврат к элементу, который их открыл, и отсутствие ловушек фокуса. Контраст
   требует измерения; он не объявляется WCAG-соответствующим по виду скриншота.
6. Отключить сеть, обновить страницу, сменить роль входа при существующей сессии.
   Не должно появляться вымышленного подтверждения записи, email или платежа.
7. На физическом Android проверить WebView, системную кнопку «Назад», клавиатуру,
   фотографии, прокрутку и переключение темы. Chromium-снимки не заменяют
   установку и приёмку APK на устройстве.
8. Большие исходники остаются открытым пунктом: получить их доступными частями
   или через поддерживаемый способ скачивания, затем расширить матрицу. Для Vertex
   требуется отдельная задача в его собственном проекте, не перенос в VIEWS.
