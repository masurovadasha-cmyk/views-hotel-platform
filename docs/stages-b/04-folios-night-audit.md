# Б4: операционное фолио и ручной ночной аудит

Начисления и сторно доступны через существующие права reservation.read/manage
и область объектов сотрудника. Баланс означает сумму начислений, а не долг
после оплаты. Банковский возврат, кассовая смена, фискальный чек и закрытие
бухгалтерского периода — отдельные незавершённые сценарии.

## Схема и API

0063 расширяет0050: дата услуги, неизменяемые команды, сохранённое распределение
ночей и уникальный запуск по объекту/дате. FORCE RLS, проверка автора, индексы,
аудит/outbox и транзакция сохраняют изоляцию.0001–0062 не переписываются.
GET /v1/folios/properties и /v1/folios используют курсоры; список начислений
доступен через /v1/folios/reservations/:id. POST charges/reversals требует
UUID Idempotency-Key. Сторно добавляет противоположную запись.

GET /v1/night-audit возвращает предварительный расчёт и revision;
POST требует ту же revision, propertyId, businessDate и ключ команды.
Расчёт использует сохранённые ночные строки и скидки: точное bigint
распределение, остаток по ранним датам. Налоги и прочие услуги не входят
в это начисление проживания и не добавляются повторно.

Дата должна завершиться по часовому поясу объекта. Неразрешённые заезды,
неполные старые снимки цен и несовпадение фактического периода размещения
блокируют пакет. Нет ограничения первых100 броней. План ночей фиксируется;
изменения после начисления требуют явной сверки. Обычный переход checked_in
в checked_out не меняет исторические условия. Результат прошлого запуска
показывается вместе с признаками новых расхождений, а не скрывает их.

## Запуск и проверка

```sh
npm run cloud:test:guest-email
npm test
npm --prefix apps/api run typecheck
```

Runner собирает клиент/Core и создаёт отдельную маркированную PostgreSQL,
применяет миграции и синтетические данные, запускает SQL/API/браузерные проверки.
Он включает VIEWS_FOLIO_PILOT_ENABLED только для одноразового теста.
Не запускайте bootstrap/seed/reset против views_local. Для постоянной установки
сначала нужен отдельный план применения новых миграций и резервная копия.

Браузерный сценарий scripts/folio-browser-core-proof.cjs использует настоящие
cookie, BFF, Core и PostgreSQL; сессия синтетически создана административной
фикстурой. Проверяются bigint, потеря ответа/тот же ключ, сторно, устаревшие
условия, две ночи, отзыв доступа, три языка и мобильная ширина.
Статус полного прогона фиксируется в CURRENT_DELIVERY_STATUS.md после запуска.

## Риски и ручная приёмка

- Бухгалтеру проверить распределение скидок и отдельно согласовать налоговый
  и финансовый ночной аудит. Текущий модуль не проводит оплату автоматически.
- На копии данных проверить ранний выезд, старые неполные снимки и переносы.
- На телефоне проверить выбор объекта, начисление, сторно и оффлайн-состояния.
- После неизвестного ответа использовать явный повтор той же команды.
  После перезагрузки сначала проверить историю: ключ формы хранится в памяти.
- Тест500 броней проверяет полноту пакета; это не подтверждение p95 или SLO.
  Полная шахматка/пагинация старых экранов ресепшн остаётся в очереди.

Публичный Core, реальная почта, платежи и фоновые расписания не включены.
