# Б2 / Б6 — отмена брони гостем

Гость открывает свою поездку, отдельно запрашивает расчёт отмены и подтверждает
показанные условия. Расчёт использует сохранённую на брони политику, время БД,
строки цены и фактически полученные платежи. В UI отдельно показаны стоимость,
собранные деньги, удержание и сумма возврата; постановка возврата в очередь не
называется зачислением на банковский счёт.

## Схема и финансовые инварианты

Новая0062 добавляет приватные расчёты и команды отмены, индексы и ENABLE/FORCE
RLS без прямого доступа runtime. booking_cancellations получает actor_kind;
старые записи/операции сохраняют staff с обязательным membership, guest имеет
реальный user_id и пустой membership. Сотрудник для гостя не создаётся.

Доступ проверяется по существующей проекции поездок: явное владение профилем
или принятое разрешение на одну бронь, соответствие организаций/объекта,
активная email-сессия. Проверка повторяется внутри транзакции после блокировок
и перед возвратом прежнего результата. Запросы расчёта/подтверждения ограничены
30 за5 минут на аккаунт. Отзыв связи закрывает также повтор команды.

Расчёт живёт до пяти минут, ближайшей границы политики или заезда — что наступит
раньше. Снимок охватывает бронирование, строки цены, политику, занятые даты,
платёжные намерения, захваты и возвраты. Изменение снимка требует нового расчёта
и отдельного подтверждения. Одинаковая команда возвращает прежний результат
после потери ответа, не создавая второй отмены/возврата.

Подтверждение освобождает даты, меняет статус и атомарно сохраняет отмену,
лимиты возврата по захватам, audit/outbox, очередь возврата и проводки через
существующий PaymentRecoveryService. Сетевых запросов провайдеру в этой
транзакции нет. Квитанция — неизменяемый результат команды: pending не является
онлайн-трекингом провайдера, а not_required означает нулевой возврат на момент
этой отмены. Поздний платёж может создать отдельный возврат. Порядок блокировок совместим с callback платежей: намерения,
затем бронь и профиль. Позднее поступление денег обрабатывается прежним
механизмом возврата для отменённой брони.

SQL независимо пересчитывает допустимость и денежные лимиты. Отложенный
constraint trigger проверяет очередь возврата и точную опубликованную пару
проводок до COMMIT, поэтому вызов SQL в обход recovery не оставит частичную отмену.

Существующие возвраты или финализированная экономика, противоречивые суммы,
неизвестная политика и неподходящий статус закрывают самостоятельную отмену
и направляют к ресепшн. Автоматического предположения «бесплатная отмена» нет.

## API, UI и запуск

Core, гостевая email Bearer-сессия:

- POST /v1/guest-identity/email/trips/:id/cancellation/preview, тело {};
- POST .../confirm, тело {quoteId}, заголовок Idempotency-Key UUID.

Cookie-шлюз использует соответствующие /guest-api/trips/... пути. Обе операции
требуют Origin, cookie и CSRF. Поля actor/organization и лишние поля тела
отклоняются. Ответы no-store и фильтруются по явному списку; суммы — строки
минимальных денежных единиц, без потери точности через Number.

Нужен отдельный VIEWS_GUEST_CANCELLATION_PILOT_ENABLED=true вместе с прежними
local/test/email gates. По умолчанию пилот выключен. Одноразовый runner задаёт
флаг сам; обычная установка и публичные web/APK не переключаются.

RU/UZ/EN: расчёт, срок действия, подтверждение, результат и сетевые ошибки.
При неопределённом результате сохраняются quoteId и ключ команды, повтор
выполняется вручную; обновление/закрытие карточки внутри поездок блокируются
до разрешения результата. Закрытие самого браузера не сохраняет незавершённую
команду на диск: после входа нужно проверить фактический статус поездки.

```sh
npm run cloud:test:guest-email
npm test
npm --prefix apps/api run typecheck
node scripts/core-network-primitive-gate.mjs
node --test scripts/staff-mail.acceptance.cjs
npm run build:review
node scripts/access-portal.browser.cjs
```

PostgreSQL16, Chromium и зависимости уже предусмотрены окружением. Новых
пакетов и платных сервисов нет. Синтетические данные создаются только после
проверки маркера одноразовой БД в guest-cancellation.integration.test.ts и
scripts/guest-cancellation-browser-proof.cjs. Persistent views_local и старые
миграции0001–0061 не меняются. Изменение setup/start конфигурации не требуется.
