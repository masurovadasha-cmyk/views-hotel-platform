# Последовательность оставшейся работы

Обновлено08.10.2026 после проверки репозитория командой. Этот список описывает
незавершённые продуктовые сценарии, а не только таблицы/контракты. Полный исходный
объём сохраняется в PRODUCT_REQUIREMENTS.md. Ориентир первого запуска —500
апартаментов в Ташкенте, Самарканде, Бухаре и Хиве.

| Очередь | Программная работа | Приёмка / внешние условия |
| --- | --- | --- |
| Б2/Б6: внешняя приёмка | Гостевая отмена реализована и проверена локально; подключить реальную доставку приглашений и платёжный возврат | Реальный возврат требует платёжного провайдера |
| Б3 | Разрешение uncertain/blocked по проверенному статусу провайдера; жизненный цикл банковского депозита; фискальные статусы и адаптеры | Контракты/API Click/Uzum, фискальный оператор, юридическая схема выплат. Журнал сверки сам по себе не подтверждает движение денег |
| Б4: финансовое продолжение | Операционные фолио/сторно/ночные начисления реализованы; далее связь с оплатой, налогами, GL и закрытием периода | Бухгалтерская приёмка; начисления не равны оплаченному долгу |
| Б4/Б7: закупки и склад | Два ролевых входа, каталог/заказ/полная приёмка/выдача реализованы; частичная приёмка и пересчёт одной позиции добавлены0066/67; далее возвраты, перемещения, массовая ведомость и поставщики | Реальные назначения сотрудников, физический учёт и согласование бухгалтерских проводок |
| Б4 | Полная пагинация собственного фонда, шахматка, атомарная смена юнита, группы и общие задачи | EXCLUDE, права по объектам,500 апартаментов. Текущие ограничения выдачи ресепшн/housekeeping не равны поддержке всего фонда в UI |
| Б5 | Очередь регистрации со сроками/напоминаниями, отчёт бухгалтеру, версии региональных сборов; загрузка документов с карантином/удалением | Реальные E-mehmon API, проверенные ставки, региональное хранилище и управление ключами; юридические условия проверить |
| Б6 | Гостевой каталог → поиск → расчёт → hold → оплата → поездка, услуги/отзывы/лояльность | Связать существующее ядро с продуктовым UI; не считать демо-экраны подключёнными сценариями |
| Б7 | Операционный календарь персонала, сохраняемые чек-листы, фото, инспекция и переназначение задач | Работа на устройстве, слабый интернет, конфликты/повторы. Сейчас подтверждены отдельные claim/release/complete сценарии |
| Б8 | Верификация хостов, модерация, споры, комиссии и выплаты; массовый импорт фонда с dry-run и отчётом ошибок | Деловые данные владельцев, операционная проверка прав, юридическая схема выплат |
| Б9 | Диалоги/сообщения/состояния доставки в БД, outbox; Telegram-бот и проверка mini-app initData; шаблоны, уведомления | Сначала надёжная доставка; WhatsApp/SMS/email/push и AI после подключения соответствующих провайдеров |
| Б10 | iCal с защитой от SSRF и конфликтов дат; подписанные партнёрские вебхуки/повторы; доступ к коду замка по времени | Канальные API, реальные замки и динамические цены после подтверждения контрактов |
| Б11 | Профиль нагрузки и p95, модель угроз, восстановление региональных ключей, репетиция импорта500, WCAG/устройства | Доказательства SLO, аварийное восстановление и юридический чек-лист до публичного Core |

Технический компромисс текущего клиента: React и Android WebView используют общую
кодовую базу. Запрошенные Next.js для SEO и Flutter/React Native не реализованы;
это отдельные архитектурные задачи, их нельзя считать завершёнными сборкой APK.

Стандарт каждого блока: совместимая миграция при необходимости, типизированный
код, отрицательные/конкурентные проверки для критичной логики, инструкция запуска,
риски, ручная приёмка и обновление существующего draft PR. Применённые миграции
не переписываются. Постоянные данные не заменяются тестовыми. Отсутствие хоста
не мешает одноразовым локальным проверкам, но не означает готовность публичного
сервиса. Новые внешние договоры/ключи не подменяются незаметными заглушками.
