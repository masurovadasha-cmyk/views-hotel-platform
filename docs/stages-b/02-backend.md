# Б2 — ядро бэкенда (в работе)

8 октября 2026, Asia/Tashkent. План: завершить тарифы, проверку доступности/прав, поиск по фонду, затем отмену с возвратом и границу гостевой авторизации. Допущение: реальных SMS/платёжных договоров нет; внешняя отправка не включается.

## Реализовано и проверено: тарифы и каталог

- `OwnerRatesService`: базовая цена UZS строкой, дневные/недельные переопределения, минимальный срок, закрытие даты/заезда/выезда. Версия данных предотвращает потерю правок; повторный ключ возвращает прежний результат, чужое содержимое ключа отклоняется. Изменение, аудит и outbox атомарны.
- `GET /v1/owner-inventory/:propertyId/rates`, `GET/POST /v1/owner-inventory/:propertyId/rates/:rateId`; GET детали требует `from/to`, POST — UUID `Idempotency-Key`. BFF: аналогичные `/local-api/owner-inventory/...`. Только уже существующий owner/manager, активный собственный объект UZ/Asia/Tashkent; `NODE_ENV=test`, `VIEWS_LOCAL_REHEARSAL=true`, `VIEWS_OWNER_RATES_ENABLED=true`. По умолчанию выключено. Нового привилегированного входа нет.
- Блокировка тарифного плана удерживается до конца расчёта: цена и дневные правила принадлежат одной версии. Старые quotes/брони сохраняют снимки, даже если владелец затем изменит цену. Дневные правки за пределами выбранного окна сохраняются; недельный набор заменяется целиком.
- Расчёт отклоняет превышение вместимости, недействительное резидентство, неактивный объект и политику другой организации. Проверка связывает активного пользователя с его членством.
- Создание, подтверждение и снятие холда проверяют `reservation.manage` **до идемпотентного повтора**. Старый ключ не обходит права. Владелец без этого права может менять тариф, но не создавать бронь от имени менеджера; роли не расширялись.
- `GET /v1/inventory-search?from=2029-04-01&to=2029-04-03&guests=2&city=...&cursor=...` и BFF `/local-api/inventory-search`: каталог сотрудников, фильтр города/вместимости/занятых интервалов, страницы по 50 с курсором, привязанным к фильтрам. Тест обходит все 500 **синтетических** юнитов. Это не публичный гостевой маркетплейс.
- Поиск использует локальные 14:00/12:00 объекта и возвращает явно обозначенную базовую цену без сборов. Окончательная цена и тарифные ограничения проверяются `/v1/quotes`; конкурентное бронирование — EXCLUDE при создании холда. Истёкшие, но ещё не снятые периоды поиск считает занятыми.

Схема цен/холдов существующая, новые миграции для этого подблока не нужны. Усиленная проверка акторов использует helper миграции Б1 0050.

## Ещё не закрыто в Б2

- Пилотная отмена по замороженной политике с частичным возвратом реализована следующим подблоком: [схема, проверки и ограничения](02-cancellation-and-refunds.md). Остались гостевая авторизация команды, интерфейс и реальная сверка с провайдером.
- Существующая гостевая авторизация привязана к уже подтверждённой брони и одноразовой ссылке. Порт SMS существует, провайдер не подключён. Это не регистрация нового гостевого аккаунта по SMS-коду. Выбор провайдера/лимиты/доставка — **проверить**, программная регистрация ещё предстоит.
- Публичный поиск с полной ценой, картой и фильтрами удобств/политики отмены — Б6; текущий поиск сотрудников не объявляется их заменой.

Ручная проверка: два менеджера редактируют одну версию тарифа; старый quote остаётся действительным до своего TTL; закрытие даты блокирует новый quote; выдача по всем городам сохраняет область доступа. Реальные цены и распределение 500 апартаментов не заданы, в рабочий фонд тестовые данные не добавляются.
